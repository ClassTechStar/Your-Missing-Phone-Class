### 第四十一章：这些工具，我一个个试过

{class="chapter-intro mb-4"}
先打个预防针：本章是 2026 年工具生态的一张"快照"，半年后它就会过时：这恰恰是本章想教会你的第一课。不是教你"用哪个工具"，是帮你建立"如何选择工具"的判断框架。当你理解了不同工具的设计哲学，你就能在任何时候做出适合自己的选择。

怎么读这一章？别当购物清单读。工具的具体功能每三个月换一茬，但"它们为什么长成这样"背后的逻辑几年都不会变。你读完应该带走的是三样东西：三大流派各自的脾气、一套给自己选型的问法、以及"换工具不慌"的底气。工具名会过时，这三个东西不会。

还有一个约定：本章提到的价格、免费额度和功能开关，一律以各家官网当时的页面为准：工具圈的行情比手机价格变得还勤。我给的是"模式"（订阅还是按量、有没有免费档、谁适合付费），不是"报价单"。要下单前，官网核对一遍，五分钟的事，省下的是几百块的冤枉钱。

阅读顺序也交代一下：先看三大流派（第一节），建立地图；再按自己的水平跳读深评（第二节到第四节）；然后看 11 月快照和模型层动态（第五节），最后拿决策树和组合方案（第七节往后的实战篇）对号入座。每节的末尾都会告诉你下一节干什么，迷路了随时回头。

先回答一个大概你最想问的问题：这些工具，跟前面几章讲的那些方法是什么关系？第三十八章打过一个好比方，智能体等于模型加上"驾驭层"（Harness）。工具就是那个驾驭层：Claude Code、Cursor、Codex CLI 的差别，本质是"怎么替你组织上下文、怎么给你留确认点、怎么管权限"的差别。所以第三十九到第四十章讲的上下文工程和需求工程，在任何一款工具里都成立：学会它们，换工具只是换个壳。

AI 编程工具的三大流派

选择工具的关键不是"哪个最好"，而是"<strong>哪个最适合你当前的场景</strong>"。三个实用的判断维度：

先选场景。

- <strong>你的编程基础如何？</strong>零基础选云端 Builder，有基础选 IDE 内置 AI，高级用户选终端 Agent。
- <strong>你的项目阶段在哪里？</strong>从零开始选云端 Builder，迭代开发选 IDE 内置 AI，维护重构选终端 Agent。
- <strong>你的部署需求是什么？</strong>快速验证选云端 Builder，严肃项目选 IDE 内置 AI，自动化流程选终端 Agent。

三大流派不是同时冒出来的，它们的先后顺序本身就是一部简明进化史。最早是"补全"：AI 猜你下一个词，你按 Tab 接受：那时候 AI 是个打字员。然后是"对话"：你选中一段代码，用自然语言让它改，这时候 AI 是坐在旁边的同事。再后来是"智能体"：你给一个任务，它自己读文件、改代码、跑命令、看结果，这时候 AI 是个接活的实习生。2026 年的三大流派，就是这三种关系各自长成的样子：IDE 内置流派同时养着打字员和同事，终端流派养的是实习生，云端流派干脆把整个工位都包给它。

三问框架怎么用？拿三个真人走一遍。一位高中生，没写过代码，想给班级做个投票页面，零基础、从零开始、快速验证，三问全指向云端 Builder：浏览器打开就能干，一行代码不用看。一位上班族，会一点 Python，想把每天重复的报表活自动化——有基础、迭代开发、要稳定运行，指向 IDE 内置 AI：边写边补，学工具和学编程同步进行。一位后端工程师。维护一个十年的老系统，要批量改几百处接口调用，高级用户、维护重构、还要进自动化流程，终端 Agent 一步到位。你看，"哪个最好"这个问题根本不存在，存在的是"这个人处在什么阶段、手上是什么活儿，适合哪个"。

三种关系还有个日常类比，帮你记住每派的脾气。IDE 内置流派像副驾：你开车，它在旁边递地图、提醒路口，方向盘一直在你手里。终端流派像代驾：你说去哪，它开车，你负责在上车前讲清规则、下车前检查车况。云端流派像网约车平台：你下单，它派车派司机，全程不用你操心怎么开：代价是你对路线的掌控也交出去了。三种模式没有高下，只有你此刻想不想握方向盘。

你握不握方向盘。

三问之外，其实还有第四问：你的账号和预算生态长什么样？已经在用某家全家桶的（比如重度 GitHub 用户、某云的年费客户），优先看自家生态里的工具——同一家生态里，代码托管、CI、密钥管理本来就是一套，接一次少一次跨工具的翻译；预算敏感的，把"有免费档、能配国产模型"的工具排前面，第 42 章讲过，模型差价能到几十倍，工具档位的差价也常年存在。四问齐了，选型基本不会跑偏。

用这套框架之前，先扫三个常见误区：

- <strong>以为工具决定上限</strong>：决定上限的是第三十七到第四十章那些方法论；工具只是把方法论执行得更快。方法论不行的人，换什么工具产出都一个味。
- <strong>以为必须"先学完再动手"</strong>：三大流派没有入学考试，各家免费档都够你试出感觉：动手一周，顶看测评一个月。
- <strong>以为选了一个就要从一而终</strong>：2026 年老手的常态是混用，规划型的做重构，快而窄的做小活（第五节细说）。工具组合像衣柜，按场合搭配，不搞忠实度。

再往深处看一层：三大流派的差别，说白了是两个旋钮的档位不同。第一个旋钮是"上下文给多少"，云端 Builder 给的是你这段对话，IDE 给的是整个工作区，终端给的是整个文件系统；给得越多，AI 想得越周全，跑得也越贵。第二个旋钮是"确认给几次"，补全模式每敲一个词都由你确认，Agent 模式是你放行一次计划、它跑完再验，云端并行甚至是你收工时才回来验收。选流派，本质上就是调这两个旋钮。后面每个工具的"性格"，都是这两个旋钮的组合。

拿同一个任务把三派过一遍，感受会非常直观。任务：给你做的记账应用"加一个导出 CSV 的功能"。云端 Builder：一句话"加导出按钮，点击下载 CSV"，它在浏览器里当场改好，你点一下试试就完事，全程五分钟，但你不知道它改了哪。IDE 内置：你在编辑器里下同样的指令，它列出要改的两个文件，改动以红绿 diff 呈现，你审完点接受：多花十分钟，但你知道每一行为什么变。终端 Agent：你进项目目录说"按 PRD 的导出需求做导出功能，完成后跑测试"，它先复述计划，你放行，它自己改完跑完，回来汇报——多花的时间换来的是它顺便把测试也写了。三派干的是同一件事，差别全在你交出去多少、拿回来多少掌控。

还有一件重要的事要现在就说清楚：流派选择不是终身制，同一个项目在不同阶段会换流派。原型期你在云端 Builder 点点点点，三个月后项目要接真实用户了，你会迁到本地 IDE；半年后要批量重构，你会开终端智能体。这不是"见异思迁"，是项目长大了的自然结果，第七节的决策树会把这套"随阶段换挡"的方法讲透。

给选型焦虑的人先喂一剂解药：选错的代价，比你想的小得多。2026 年的主流工具几乎都有免费档，选错的成本通常是一个下午；而"不敢选、一直不开始"的成本，是永远停在门口。你真正要避免的只有一种错：在没想清楚需求的情况下，为工具和档位提前花大钱，先免费跑起来，用量会告诉你答案。工具选择是所有决策里"可逆性"最高的一种，别把它当成高考志愿来对待。

下面按流派逐一进去逛。每个工具都按同一张档案卡讲：定位、强项、弱项、价格模式、适合谁、上手路径，你不一定都用得上，但逛完一遍，选型的感觉就出来了。

##### 进深评之前：三张快照连起来看

第六节有一句结论——"2024 年 GitHub Copilot 是王者，2025 年 Cursor 取而代之，2026 年 Claude Code 异军突起"：值得现在就展开，因为它解释了流派格局是怎么长出来的。2024 年，AI 编程等于"补全"：谁家补全准，谁就是王者，Copilot 独占鳌头。2025 年，AI 编程升级为"对话加多文件编辑"：Cursor 用编辑器级的体验把对话焊进了日常，王座易主。2026 年，AI 编程再升级为"自主执行"：Claude Code 把战场从编辑器拉到整个终端，Agent 模式全面开花，连 Cursor 3 自己都把重心转了过去（Agent 使用率反超 Tab 就是那个转折的注脚）。

三年三王，各代表一个阶段；而每个新王出现，旧王并没有死，Copilot 现在是全家桶，Cursor 现在有终端和云端产品线。工具史的趋势不是"你死我活"，是"层累叠加"：每一代能力都沉淀为上一代工具的新功能。看懂这条规律，你就不会被"某某工具杀疯了"的标题牵着走，真正的变化是"AI 和你的关系"在一步步加深，工具只是在追赶这个变化。

#### 二、IDE 内置 AI 流派

IDE 内置 AI 是最主流的流派：把 AI 能力嵌入到你的代码编辑器里，在保留传统编程体验的同时叠加 AI 增强。2026 年这个流派的代表是 Cursor 3、Trae、Windsurf 和 CodeBuddy。

先解释一个词。IDE 就是"集成开发环境"，说人话：写代码的专用编辑器，带文件管理、语法高亮、一键运行这些配套。你以后会反复见到 VS Code 这个名字，微软出的免费编辑器，全球用得最多，下面好几个工具都以"VS Code 的加强版"面目出现。

为什么它是最主流的一派？因为它的升级方式最"温和"，你原来的编程习惯全部保留，AI 是叠加上去的，随时可以关掉。习惯了传统编辑器的人零迁移成本。公司也不用来一次"全员换工具"的大手术。这个流派吃下了最大的用户基数，反过来又让各家厂商把最好的功能都先往这里塞，主流就是主场。

##### 1. Cursor 3

Cursor 是目前全球使用最广泛的 AI 编程 IDE。2026 年 4 月发布的 Cursor 3 标志着 AI 编程工具的一个重要转折点：<strong>Agent 模式的使用率首次超过 Tab 补全模式</strong>——开发者从"AI 帮我补全代码"转向了"AI 帮我完成任务"。Cursor 3 的核心特性包括：多文件编辑（AI 可以同时修改多个文件来完成任务）、上下文感知（自动理解项目结构和依赖关系）、与终端的深度集成（AI 可以在编辑器内直接运行命令和查看输出）。

一句话画像：它是"VS Code 的深度 AI 改装版"，界面、插件、快捷键都和 VS Code 几乎一样，你会 VS Code 就会它；差别在于 AI 能力长在骨头里，而不是外挂了一个插件。这个"长在骨头里"是质变：AI 能读到整个项目的结构，而不只是你当前打开的那个文件。

<strong>强项</strong>：Agent 模式的多文件编辑最能打。你说"给设置页加一个深色模式开关"，它自己找出相关文件、改样式、改状态管理，把一串改动摆在你面前逐个确认——你从"写代码的"变成了"审代码的"。Tab 补全也仍是第一梯队，第五行要写什么，它经常猜得比你手敲还快。上下文感知让它对大项目的理解超出单文件，这是它和普通插件的分水岭。

<strong>弱项</strong>：吃资源——老电脑开大项目，代码索引那一下能让你风扇起飞（程度视机器而定）。模型走的还是第四十二章那几家，国内访问的网络门槛一样存在，订阅支付也可能卡壳。另外 Agent 模式时不时"自信越界"：改了不该改的文件。所以审 diff 的习惯必须养成——它改了什么，你要看得见。

<strong>价格模式</strong>：免费档有次数限制，尝鲜足够；Pro 档按月订阅（第 42 章那张表里有具体数字），日常开发基本够用；团队档再加管理后台和隐私模式。哪档划算取决于你的用量形状——先跑一周再选档，第五节会讲这笔账怎么算。一个选档小技巧：盯着你撞限额的频率选。一周撞两次以上的，直接升档——撞限额省下的订阅费，远抵不上你等额度恢复时断掉的思路。

<strong>适合谁</strong>：有编程基础、每天都要写代码的人；尤其是从 VS Code 迁移过来几乎零成本的那群人。想体验"AI 接任务"但暂时不想碰终端的，它也是最佳中转站。

<strong>上手路径</strong>：第一步，官网下载安装，打开你手头真在做的项目文件夹——不是新建练习项目，真项目才有真反馈。第二步，前三天只用 Tab 补全和行内编辑，摸清它的脾气。第三步，开 Agent 模式，先给小任务："给这个函数加错误处理。"第四步，按第 39 章的方法建好项目规则文件——这步做完，它的产出会肉眼可见地收敛。第五步，每周复盘一次：哪些活值得交给 Agent，哪些自己动手更快。

给你一个真实感十足的 Agent 场景，感受一下审 diff 是什么体验。周三晚上十一点半，你让它"把用户列表的接口加上分页"。它先在对话框里列计划：改后端的路由和数据查询、改前端的列表组件、加一个页码控件：三处文件，各改什么。你点了确认。几十秒后三个文件的红绿改动摆出来：后端多了个页码参数，前端把"一次取全部"改成了"按页取"，还顺手把页码控件做出来了。你逐块看，发现它把每页条数写死成了二十：你在规则文件里补一行"每页条数走配置，不写死"，下一轮它就记住了。整个过程你一行代码没写，但每一个决定都是你拍的。这就是"审代码的"角色：不写，但负责对与不对。

<strong>两个进阶用法</strong>，给已经上手的人。其一，Tab 和 Agent 有各自的节奏，别硬分高低：改一两行用 Tab 最快，动三个文件以上才开 Agent——把大炮留给阵地战。其二，规则文件值得持续养：每次发现它"又自作主张了"，别光在心里吐槽，把规矩写进规则文件——这个文件越养越懂你，换电脑、换项目都能带走。这两个用法都不在教程里，用两周你自己就会悟出来，这里先给你提个醒。

新手常见的三个误用，顺手纠正。误用一：一上来就开 Agent 让它"做一个完整的 App"，任务太大，它自由发挥的空间也大，产出基本靠运气。先从小任务喂起。误用二：不审 diff 全部接受，快是真快，坏也是真坏，出了问题你连哪来的都不知道。每次都过目，哪怕扫一眼。误用三：把对话当聊天窗，任务描述一句半句：它是副驾不是读心者，第四十章的五要素在这派工具里照用不误。

##### 2. Trae

Trae 是字节跳动推出的 AI 编程 IDE，在国内市场有较大的用户基数。它的 SOLO 模式（也称为 Builder 模式）是典型的"一句话创建项目"能力，你描述需求，AI 自主完成从项目初始化到代码生成的全流程。Trae 的优势在于<strong>中文支持和国内网络环境适配</strong>，适合国内用户快速上手。

一句话画像："对中文用户最友好的 AI IDE"：界面是中文的，对话用中文毫无违和，国内网络直连，不用操心海外订阅的那道坎。对第一次想"凭空变出一个东西"的人，SOLO 模式的爽感是最直接的：一句话下去，从项目骨架到能跑的页面一条龙。

<strong>强项</strong>：中文场景扎实——注释、命名、文档用中文都自然；国内网络无门槛；SOLO 模式把"从零到能跑"的摩擦压到了最小。学生党的第一个项目，用它的成功率比直接上英文环境高不少。

<strong>弱项</strong>：年轻。插件生态和社区沉淀比老牌编辑器薄，遇到冷门问题能搜到的资料有限；深度定制能力也在追赶。大型工程上的表现，以你自己的实测为准——别光看演示视频，演示视频不看项目复杂度。

<strong>价格模式</strong>：有免费可用额度，具体额度和付费档位以官网为准——这类产品的额度规则变化快，下单前看一眼当月页面，别用三个月前的攻略。

<strong>适合谁</strong>：国内用户、学生、以及"想先体验 AI 造物感"的新手。它是 IDE 流派里上手摩擦最小的一个。很多人的路径就是 Trae 入门、Cursor 进阶——两个都是 VS Code 系，切换成本很低。

<strong>上手路径</strong>：官网下载安装、用 SOLO 模式造一个小东西（班级投票页、个人主页）找手感、切到普通对话模式给它一个真实小任务、感觉不够用了，再去看 Cursor 或终端流派。每一步都别跳，跳步省下的时间会在后面加倍还。

SOLO 模式值得单独给一段，因为它代表了一种新的使用姿势。周一晚自习，一位大三学生想给班级做个投票页。他打开 SOLO，输入："做一个班级聚餐投票页，能添加选项、单选投票、实时显示票数，手机上能用。"十几秒后页面骨架出来了，他点开预览，投了一票试试，能用。接着他提了三个修改："加一个截止时间""投票后显示结果""按钮换个绿色"，每条一句话，页面跟着改。四十分钟后，他把链接发到班群。全程他没见过一行代码，但每个需求都是他用大白话讲清楚的，注意，这恰恰是第四十章练的能力：讲得清，才做得出。

SOLO 模式的边界也要说清。它擅长"从零到能跑"，不擅长"从能跑到精细"：逻辑复杂到一定程度（权限、并发、对账这种），一句话的粒度就不够了，需要回到正经对话模式逐步改。另外一句话创建的项目，初始结构是它选的——如果你后面要长期维护，记得让它解释一遍项目结构，或者按第 39 章补一份记忆文件，别让项目变成"只有它看得懂的仓库"。

SOLO 造出来的项目，收尾有三个动作别省。动作一：让 AI 讲一遍项目结构："这个项目分了哪几块？数据存在哪？"听完你的项目才真正"属于你"。动作二：把项目概述和约定写成记忆文件（第 39 章的方法），以后每次对话自动带上。动作三：导出一份代码存到本地或代码仓库，云端再方便，副本得在你自己手里。三个动作二十分钟，换来的是一个"拿得住"的项目。

也说说谁不适合它。要接手大型老工程的，插件生态薄的问题会被放大；要深度自定义快捷键和插件的，年轻编辑器的可定制性还在追赶；公司规定必须用特定海外工具链的，那更没得选。除此之外，国内个人用户想入门 AI 编程，它都是候选名单上的第一位，不是因为最强，是因为最顺。

##### 3. 其他工具

Windsurf（原 Codeium）以流畅的代码补全体验著称，适合追求"打字如飞"体验的开发者。腾讯云 CodeBuddy 作为 VS Code 插件。擅长与云生态集成，适合计划部署到腾讯云或开发微信小程序的项目。阿里通义灵码和百度 Comate 也提供了类似的 IDE 集成体验，各自在中文场景优化上有特色。GitHub Copilot 也早已不止补全：agent mode、CLI、PR 集成都有，团队里最好推的往往还是它。

这一段信息密度大，拆开说说。Windsurf 的看家本领是补全的"跟手感"，键感流畅、打断少，写代码像有人帮你扶着笔。它的智能体能力也在持续更新，但如果你主要图"打字如飞"，它值得单独一票；如果你要"整段任务交给 AI"，前面两位更对口。

腾讯云 CodeBuddy、阿里通义灵码、百度 Comate 可以放一起看：都是云厂商家的 IDE AI，共同强项是中文场景和自家云生态，CodeBuddy 跟腾讯云和微信小程序的开发链路咬合紧，通义灵码和 Comate 在中文问答、企业私有化方案上各有特色。选它们的理由通常不是"AI 更强"，而是"我的项目本来就在这家云上"。如果你的项目要部署在对应云、或者公司有对应的合规要求，用自家的顺手；纯个人项目，按功能对比选即可。

这一批怎么快速试？给你个"半天试用法"：挑同一个真实小任务（比如给一段代码加注释加测试），分别在两个工具里跑一遍，比三样东西：补全的跟手感、对话的理解力、报错时的解释质量。半天下来你会有一手感受，这比任何测评文章都可靠，因为任务是你自己的，代码是你自己的，判断标准也是你自己的。

顺手交代这批工具的共性弱点，免得你踩了坑怪自己：它们的 Agent 能力普遍比第一梯队"温"一点，接大任务时更保守，需要你把任务拆得更碎。这不是坏事，反而逼着你练第四十章的拆解功，但你得心里有数，别拿"让它独立完成大重构"当验收标准。

##### 4. GitHub Copilot：最早出圈的全家桶

一句话画像：AI 编程的"启蒙者"，2021 年就以补全出圈，如今是"最不会出错的选择"。它从补全起家，现在 agent mode、CLI、PR 集成都齐了，按第五节快照的分类它算编辑器内智能体，但实际已经是全家桶。

<strong>强项</strong>：和 GitHub 生态咬合最深。代码放在 GitHub 上的人，从写代码、审改动到合并上线一条线不用换工具；agent mode 能接任务，PR 集成能帮你审别人的代码——团队协作场景它是独一份的顺。补全质量常年第一梯队，中文对话也没问题。

<strong>弱项</strong>：单点能力不如专精选手极致——自主干活的狠劲比不过终端流派那几个"专业实习生"；深度绑定 GitHub，代码不在 GitHub 上的人体验打折。免费档额度有限，重度使用要付费。

<strong>价格模式</strong>：有免费档（有限额度）；付费档按月订阅；学生和教师认证后有优惠，具体政策以官网为准。团队采购按人头计费——公司里"给大家统一配个 AI 助手"，多数时候答案就是它，因为管理后台和合规配套成熟。

<strong>适合谁</strong>：已经在用 GitHub 的所有人；学生（认证优惠）；以及一切"团队里要统一工具"的决策者。<strong>上手路径</strong>：几乎零门槛——装插件、登录、开始写代码，补全自动出现。想用 agent mode，把任务用一句话写进对话框就行。它也是三大流派里"第一天就有产出"体验最好的一个。

给你一个团队场景，看看它和单机 IDE 的分野在哪。周四下午，五个人的小组要合并一周的改动。组长的做法：把 PR（合并请求，可以理解为"改动打包待审"）推到 GitHub，让 Copilot 先过一遍——几分钟后它列出三条意见：某个函数没处理空值、两处命名和项目规范不一致、有一条改动和另一条分支冲突。人再来复审，二十分钟收工。AI 审查替代不了人，它不懂你们的业务内幕，但它把"低级问题"提前筛掉了，人只讨论真正要拿主意的事。

免费档的用法边界也说一句：它适合"每天零散用几次"的节奏，补全随便用，Agent 类功能省着点。如果你发现自己连续一周天天撞免费墙，那不是工具的错，是你的使用强度已经进入付费档的目标区间了，升档反而划算。

##### 5. WorkBuddy：办公与轻量开发的跨界选手

把 WorkBuddy 放进来要先说明：它不是传统意义的编程工具。第十三章讲 AI 办公软件时介绍过它，定位是职场办公助手，会议纪要、邮件、汇报、文档的起草润色总结一条龙，部分工作流在手机端发起、重活放电脑端完成。把它列进"工具全景"，是因为 2026 年的工具边界正在变模糊：办公助手们开始能碰简单的数据处理和轻量脚本，很多人正是从"让 AI 帮我整理表格"开始，一步步滑进了编程的门口。

给你一个手机端发起的工作流，感受这种"跨界"怎么落地，周五下班前的地铁上，你想起下周要给领导汇报数据看板的事。打开 WorkBuddy，口述一段："把本周的迭代记录整理成汇报提纲。分背景、进展、风险三块。"到公司后切到电脑端，提纲已经在草稿箱里，你补上数字和截图，半小时的活二十分钟干完。它没写一行代码，但你下一周让 IDE 改看板时，那份提纲顺手就变成了需求说明，办公工具和编程工具的接力，就是这么发生的。

<strong>怎么用它最合理</strong>：把它当"编程世界的门外汉席位"。写周报时，让它把本周的代码提交记录整理成人话汇报；做新项目前，让它把聊天记录里的需求归成五要素卡——它不替你写代码，但把"代码之外"的环节包了。真要写代码，还是回到前面那些 IDE 和终端工具。它的价值在于提醒你：AI 编程不只是写代码那一环，需求整理、进度汇报、文档维护同样是工程的一部分（第四十章讲的需求文档，很多就是在它这类工具里起草的）。

边界也要划清：办公助手的"轻自动化"不要拿来干正经过工程的活。让它在文档里拼几行示例代码可以，让它改你项目的代码不行，它没有项目上下文，也没有版本控制意识，改坏了你连回滚的地方都没有。一句话记住它：它管"说清楚"，不管"做出来"。另外它这块的具体功能随版本更新较快，以官方说明为准。

#### 三、终端 Agent 流派

终端 Agent 是 2026 年增长最快的流派。核心理念：<strong>AI 不应该只是一个编辑器插件，它应该能像开发者一样操作整个开发环境</strong>——读写文件、运行命令、查看输出、安装依赖。Claude Code 是这个流派的代表。

先给没用过终端的读者补五秒课。终端就是那个黑底白字的命令行窗口——你打字下命令，电脑执行后回你结果，没有按钮，没有图标。苹果和 Linux 自带（就叫"终端"），Windows 有自带版本也有更好用的替代品。听着很"极客"，但它其实是电脑最诚实的操作界面：你做了什么、电脑回了什么，全都有文字记录。AI 编程选它当主场，看中的正是这份"全有记录、全可执行"。

##### 1. Claude Code

Claude Code 是 Anthropic 推出的终端 AI 编程工具，到 2026 年中期已达到年化收入 25 亿美元的规模。它的工作方式与传统 IDE 完全不同：你在终端中用自然语言描述任务，Claude Code 会自主读取相关文件、修改代码、运行测试、查看结果、迭代修正，整个过程不需要你打开编辑器。

Claude Code 的优势在于"全项目感知"：它不受编辑器窗口限制，可以自由地浏览整个项目目录，理解文件间的依赖关系。它也支持 CLAUDE.md 项目记忆文件，让 AI 在每次会话开始时就了解项目背景。对于大型项目的重构、批量修改、测试编写等任务，终端 Agent 少一件 IDE 插件会顾此失彼的事：它能翻出你没打开的那个文件。

一句话画像："住在终端里的资深工程师"。没有花哨界面，一个命令行窗口，你说任务，它读代码、改文件、跑测试、看输出，干完向你汇报。第一次看它自动跑起来的人多半会愣几秒，那个感觉不像在用工具，像在带人。年化收入 25 亿美元意味着什么？意味着有一大批专业开发者真金白银地为"这个感受"付费，它不是玩具。

<strong>强项</strong>：全项目感知是底座，跨文件的大改动是它的主场——"把所有旧接口调用迁到新的封装层"这种活，IDE 插件会顾此失彼，它能一处处找出来、改完、跑测试自证。hooks、子代理、SDK 把它做成了可编排的基础设施，第五节快照里它是 MCP 生态最全的一个。先规划后动手的默认习惯，让它在大改动上的"闯祸率"相对可控——你会先看到计划，再放行执行。

hooks 和子代理这两个词后面会反复出现，用五句话解释清楚。子代理：主智能体把"读代码库""跑测试"这类活分派给临时的小助手，它们各自埋头干活，只把结论带回主线：主对话不会塞满几千行日志。hooks：你预先设置的自动动作，比如"每次它要改文件，先自动跑一遍检查脚本"，相当于给实习生配了个门禁。SDK：开发者用它把 Claude Code 的能力嵌进自己的程序里，普通读者暂时用不上。知道有这回事就行。这些能力合起来，就是"可编排"三个字的含义：它不只是对话，是能被你排兵布阵的一支队伍。

<strong>弱项</strong>：两个门槛。一是终端本身：没碰过命令行的人第一天会懵，这是它对零基础用户最不友好的地方。二是成本：自主跑任务就是实打实的模型消耗，订阅档有额度上限，重度使用前先看看自己的用量形状（第 42 章讲过怎么算这笔账）。另外它有时过于谨慎，该动手的地方反复跟你确认；学会调自治级别，是用好它的必修课。

<strong>价格模式</strong>：跟着 Claude 的订阅走（第 42 章那张表里有 Pro 档的月费），也有按 API 用量的玩法，具体额度规则以官方文档为准。给你的建议就一句：先想清楚你的项目值多少自动化，再决定上哪个档。

<strong>适合谁</strong>：有终端使用习惯的开发者、维护大项目的人、想给工作流装"自动化手臂"的进阶玩家。零基础读者别硬冲——先把云端 Builder 和 IDE 玩熟，终端流派跑不了。

<strong>上手路径</strong>，五步：第一步，照官方文档装好，在终端里进入你的项目目录。第二步，第一个任务给小的："给 src/utils 里的日期函数补上单元测试。"小任务建立信任，大任务才敢放权。第三步，按第 39 章写好 CLAUDE.md，它理解项目的方式会立刻不一样：项目结构、命名习惯、常用命令，它一进目录就知道，你不用每次从头解释一遍。第四步，学会看它动手前的计划——批准、驳回都要敢按，你的判断就是它的护栏。第五步，把高频动作固化下来（自定义命令、hooks，以官方文档为准），让它从"实习生"长成"老搭档"。

把第一次对话拆成六步，每步都写上"屏幕上会看到什么"，零基础的读者可以照着走：一，打开终端窗口（黑底白字那个）；二，输入进入项目目录的命令，回车，提示符里的路径变成了你的项目名；三，输入启动命令加一句话任务，回车，它会先"读"一阵子，屏幕上滚动出它正在查看哪些文件，四，它列出计划：要改哪些文件、跑哪些命令——这是你审阅的时刻；五，你确认放行，它开始改，屏幕上持续出现文件名和进度；六，它汇报结果，你按它给出的验证命令跑一下。确认没坏，收工。整个过程你敲的字不超过两行，但每一步你都看得见、拦得住。

一个深夜场景帮你建立体感。凌晨一点，你接手一个前任留下的项目，三百个文件无从下口。以前的做法：通宵读代码。现在的做法：进终端，敲一句"给我讲讲这个项目的结构，重点说数据流和入口文件"。两分钟后，它给你一份三段的导读：入口在哪、数据怎么走、哪些模块最老最脆。你接着问"如果要加一个导出功能。该动哪几个文件"，它列了四个文件和先后顺序。你这才第一次真正"看清"这个项目——而你没有读一行代码。这就是全项目感知的日常用法：它不替你写代码时，也在替你读代码。

##### 2. Codex CLI 与 Aider

OpenAI 的 Codex CLI 提供了类似的终端编程体验，并支持用 /init 生成 AGENTS.md，让 AI 理解现有代码库的约定。Aider 是一个开源的终端 AI 编程工具，支持多种模型（GPT、Claude、DeepSeek 等），适合想要灵活切换模型的用户。Google 的 Gemini CLI 也加入了战团：上下文窗口大。个人账号还有免费额度，适合想零成本先试试终端智能体的用户。这些工具虽然各有特色，但核心理念一致：<strong>让 AI 在终端中拥有完整的开发环境操作能力</strong>。

Codex CLI 的性格可以用一个词概括：先把规矩讲清楚再干活。开工前它让你声明自治等级，是只给建议不动手，还是在沙箱里自动跑，界线画清了它才出门。沙箱是个隔离环境，它在里面怎么折腾都不碰你系统本体，跑完把结果呈给你。代码开源可读，想研究它怎么工作的，源码就在那里。

/init 值得单独表扬。接手老项目的第一件事，建议就是跑一次 /init：它会把代码库的约定——目录结构、命名习惯、常用命令，整理成一份 AGENTS.md，相当于新同事入职第一天自己写的调研报告。你只需要修几笔（把错的改对、把漏的补上），之后每次会话它都带着这份约定干活。这个动作五分钟，省的是后面每一轮对话的反复解释，第三十九章讲的项目记忆文件，在 Codex 这边就是这么落地的。

自治等级怎么选？给你一个朴素的对照：纯只读（只分析不动代码）适合"我只想搞懂这个项目"的时候；沙箱内自动跑适合日常任务，改坏了也出不了隔离区；完全放开留给成熟项目加成熟规则的场景，新手前一个月别碰。等级不是越低越好，太低的等级会让你沦为"逐字批准机器"，效率掉到比手写还慢：挑"改坏也兜得住"的最高档，才是对你效率最好的档。

Aider 的性格是另一个词：老兵。开源、模型无关，GPT、Claude、DeepSeek 都能接——你自己的 API Key 自己充值，花多少一目了然，配第 42 章讲过的国产模型能把成本压得很低。它还有个对新手特别友好的习惯：每次改动自动做一次 git 提交——每一步都留下脚印，出问题一条命令就能回到上一步。对总怕"改坏了回不去"的人来说，这张隐形安全网比功能列表上任何一项都值钱。代价是配置全靠自己：装 Python、配环境、填 Key，DIY 乐趣和上手成本是一体两面。

给这两个工具各补一句"适合谁"。Codex CLI 适合看重边界感的人：你在意"AI 到底被允许干什么"，在意改动必须发生在沙箱里，它的哲学跟你合拍。Aider 适合预算敏感、动手能力强的人：学生、自学者、"我就想用最便宜的办法试试"：它把工具的门槛换成了配置的门槛，愿意花半小时配环境的人，换来的是完全透明的成本和自由。两家的上手路径在各自官方文档里都写得很清楚，照着敲就行，这里不重复。

Aider 加国产模型是个值得单独点的组合。它模型无关，接上第 42 章讲过的国产模型（比如兼容各家协议的 DeepSeek），日常小任务的成本能压到很低，注意 8 月调价后成本要用新价目重算。这个组合的哲学是"把工具层的钱省下来，花在模型层该花的地方"：编辑器免费开源，模型按量付费，每一分钱都看得见去向。适合预算敏感但用量稳定的自学者；用量飘忽的，订阅制反而省心。

同一个 bug 在两派的修法差异，再给你看一眼。一个"保存后偶发丢失数据"的 bug：IDE 里你选中相关代码让 AI 排查，它看着你给的这段说"逻辑没问题"，你就卡住了，因为真凶在另一个你没打开的文件里。终端里你给 Claude Code 一句"保存偶发丢数据，帮我定位"，它自己翻出存储层和调用层两个文件，对出了时序问题，改完写了个复现测试。不是谁更聪明，是它有机会看全——工具的差距，很多时候是"视野"的差距。

##### 3. Gemini CLI：免费试水的门

Google 的 Gemini CLI 值得单独一小节，因为它的定位很特殊：终端流派的"体验门票"。上下文窗口大是它的天然强项，第 42 章讲过 Gemini 系列的上下文优势，反映到 CLI 上，就是它能一口气吞下更大的代码库；个人账号还有免费额度，你想感受"终端里养一个智能体"是什么滋味，它可以做到零成本起步。

怎么用这段免费额度最值？别拿它做正经项目，拿它"学流程"：装好、进项目、给它讲一次项目结构、让它做一个小任务、看它列计划、放行和验收，把终端智能体的完整流程走熟。等你对"先计划后放行"的节奏有了手感，再换到生态更全的主力工具，几乎无缝。它的短板也照实说：编程打磨的精细度对比前面两位还有差距（以你实测为准），生态和扩展性在追赶中——当体验门票完美，当生产力主力还差点火候。

到这里，终端流派的三种性格加一张门票就齐了：谨慎的规划型（Claude Code）、规矩前置的沙箱型（Codex CLI）、开源自由的 DIY 型（Aider）、零成本试水（Gemini CLI）。给你一张"终端流派速选"的快表：

- <strong>要"先规划后动手"、生态最全</strong>：Claude Code，hooks、子代理、MCP 都齐，大项目首选。
- <strong>要"边界清晰、沙箱运行"</strong>：Codex CLI，自治等级先声明，接手老项目先 /init。
- <strong>要"成本可控、自由组合模型"</strong>：Aider：自带 Key 按量花钱，自动提交兜底。
- <strong>要"零成本先感受流程"</strong>：Gemini CLI，个人账号免费额度，学节奏的好教具。

##### 4. 终端流派的安全护栏：自由越多，护栏越多

终端流派的一切优势都建立在"AI 能操作整个环境"上，而这恰恰也是它的风险来源：能删文件、能跑命令的实习生，得有明确的边界和监督。护栏四件套，照着配：第一件，git，开工前确认项目已经提交过，改砸了随时回到原点，Aider 的自动提交就是把这个习惯固化了；第二件，权限确认——新手阶段保持"每步都问我"，熟了再逐步放权；第三件，沙箱与自治等级——能圈在隔离环境里的任务，别放它出来跑；第四件，项目记忆文件里的规矩："哪些目录不许动""哪些命令禁止执行"写成白纸黑字。这四件配齐，终端智能体的"闯祸空间"就被压到了可控范围；第 45 章的质量保障流程，再补上验收环节的最后一块板。

下一派把自由推得更远：连环境都不要了，直接在云端开工。

#### 四、云端 Builder 流派

云端 Builder 是最适合零基础用户的流派。你不需要安装任何软件，只需要打开浏览器，描述你的需求，AI 就会在云端创建完整的项目，并提供即时预览。

- <strong>v0</strong>（Vercel 出品）：擅长生成前端 UI 组件和页面，适合快速制作网页原型。
- <strong>Bolt</strong>：支持从一句话创建全栈应用，包含前端、后端和数据库。
- <strong>Replit Agent</strong>：在 Replit 的云端 IDE 中工作，不仅能创建项目，还能直接在云端运行和部署。

这些工具的共同优势是"<strong>零配置上手</strong>"，打开浏览器就能开始。局限在于：当项目变复杂后，云端编辑环境的灵活性不如本地 IDE。因此它们最适合"从 0 到 1"的原型阶段：用云端 Builder 快速验证想法，验证通过后再迁移到本地 IDE 进行深度开发。

这个流派的体验值得单独描述一遍，因为没试过的人想象不到它的"平"：打开网页，一句话，十几秒后屏幕上出现一个能点的页面——不是设计稿，是真页面。改个颜色，说一句话；加个表单，说一句话。整个过程你的手不需要离开鼠标，手机浏览器上甚至也能完成一轮迭代。这种"零摩擦造物"对第一次接触的人冲击很大：很多人就是从这里相信"我也能做东西"的。

三家的性格差异说清楚，方便你挑。<strong>v0</strong> 是"UI 专精选手"：前端页面和组件的生成质量是其招牌，跟 Vercel 的部署链路一体，做给人看的页面：作品集、活动页、演示原型，它最快；后端和复杂业务逻辑不是它的主场。<strong>Bolt</strong> 是"全栈快手"：一句话给你前端、后端加数据库的整套，即时预览跑通全流程，验证"带后端的小想法"最合适；项目复杂之后，云端环境的约束和用量成本会逐渐显现。<strong>Replit Agent</strong> 是"云端一条龙"：创建、运行、部署全在 Replit 的云端 IDE 里完成，手边只有平板或借来的电脑也能干活，教学场景尤其合适；代价是环境在别人家，深度定制和依赖的自由度不如本地。价格模式三家大同小异：免费档加按用量升级，具体额度以各家官网为准。

上手第一小时怎么度过？三家路数差不多，以 Bolt 为例走一遍：注册登录后，把需求写成一句话丢进去：注意，是按第 40 章加工过的那句话，不是"做个 App"；十几秒后预览窗口出现能点的页面，你把核心流程点一遍，哪里不对就用一句话提；五到八轮后核心功能像样了，连上它给的示例数据试试边界情况；满意了，找到导出（或连接代码仓库）的入口，把源码收进自己口袋。整个流程不需要任何安装，整个过程每一步都有画面可看：这就是"零配置"三个字的含义。

给手机党一个专门的提示，毕竟这是一本手机课：云端 Builder 在手机浏览器上能完成"描述、预览、迭代"的大半闭环，说需求、看效果都顺畅，精细的修改在手机小屏上会吃力些。所以现实的最优解是混合用法：想法冒出来时在手机上先丢给云端工具起个雏形，回头在电脑上精修。碎片时间负责"从 0 到 0.7"，整块时间负责"从 0.7 到 1"，通勤和深夜的时间都不浪费。再叠加第十三章的远控方案，手机还能远程指挥电脑上的 IDE 和终端工具：手机在这个体系里的角色，是"随时在线的指挥席"。

{class="font-semibold"}
避坑提醒：别把原型当产品

云端 Builder 造出来的东西，"看着像产品"和"是产品"之间隔着一整个第 45 章，没有测试、没有备份、没有像样的错误处理。它的正确归宿是验证想法，然后导出代码迁到本地深度开发。数据和应用务必在本地留副本：见过有人用云端工具跑了半年业务，一次平台策略调整就把自己架在火上。

迁移这件事再强调一句：主流云端 Builder 都支持把代码导出（或连到 Git 仓库），所以"从 0 到 1 在云端，从 1 到 100 在本地"是 2026 年被走得最多的健康路径，原型期的爽快和工程期的扎实，两样都拿到。导出之后别急着关浏览器：先在本地把项目跑起来，确认环境没问题，再开始深度开发。

给你一个完整的"云端原型日"时间表，照着玩一天就知道这派值不值得进你的工具箱。上午十点，一句话起项目；十点十分，核心页面出来了。你连提五轮修改；十一点，接上它提供的示例数据，把主要流程点通；中午吃饭前，把三个"看起来想做"的想法记进 backlog，不急着做。下午两点，处理最硬的那个功能，发现云端环境有点吃力，记下来，这是要迁到本地做的信号；三点，导出代码到本地，试着跑通；四点，跑通了，写一页纸 PRD（第 40 章的），给这个项目定了性：值得继续做。一天下来，你完成了一次完整的"从想法到立项"——这在 2023 年要一周，在 2026 年只要一天。

首日常见翻车也提前说三个。翻车一：需求只丢半句，"做个商城"，然后对着产出说"不是这样"；按第 40 章加过工的句子才能进来。翻车二：光看不说，预览出来了只顾着惊讶，不把核心流程点一遍；它的对错要靠你的点击喂出来。翻车三：忘了导出——玩得开心，关了浏览器，三天后想继续找不回去（多数平台有历史记录，但别赌这个）。三件事避开，第一天的体验会好一大截。

数据安全顺带答一句，这是被问得最多的：你的需求描述和项目内容会存在厂商的云上，敏感数据（真实用户信息、公司机密）别往里放，用假数据做原型是行业惯例；各家隐私政策不同，以官方说明为准。一句话原则：云端 Builder 上跑"想法"，不跑"家底"。

#### 五、快照修订：2026 年 11 月

前面的快照停在 2026 年 8 月。到 11 月回头看，没变的是"按工作方式分派系"，变的是每个派系里多了哪些玩家，以及它们开始共享同一套约定：MCP、AGENTS.md、子代理、hooks。按派系把新格局过一遍：

- <strong>终端智能体</strong>：Claude Code（先规划后动手、hooks、子代理、SDK，MCP 生态最全，默认谨慎）；Codex CLI（先声明自治等级、在沙箱里跑、开源可读）、Gemini CLI（上下文窗口大、个人账号有免费额度）；Aider（老牌、模型无关、每次改动自动 git commit）。适合脚本化、SSH、CI。
- <strong>编辑器内智能体</strong>：Cursor（编辑器与智能体一体，也提供 CLI 与云端智能体）、GitHub Copilot（agent mode、CLI 与 PR 集成）。diff 就出现在你平时读代码的地方。
- <strong>开源 / 自带模型</strong>：Cline 一类提供显式 Plan/Act 切换与本地模型接入，胜在透明、可控成本，代价是自己动手配置。
- <strong>云端并行智能体</strong>：把一串定义清楚的任务丢进隔离环境并行跑，回来的是 diff 与测试结果。适合"工单队列"，不适合边想边做。
- <strong>不必只选一个</strong>：2026 年老手的常见做法是混用——谨慎的规划型做重构，快而窄的做小改动，各自绑到不同仓库。

##### 模型层的三件大事

工具快照之外，模型层在 9 月到 11 月也翻了页。第一件：OpenAI 的 GPT-6 系列于 9 月 22 日发布，家里三个成员，Sol、Luna、Astra，旗舰是 Astra，定价约为上一代的一半（详见第 42 章的专段）。对工具用户的直接影响：各家工具背后的"发动机"开始换新，同样的任务描述，产出质量和能扛的工作量上限都在变，你的工具体验会"无感升级"，但超额额度烧得也更快，档位值得重新核一遍。

第二件：Anthropic 的新主力是 Claude Opus 5.5。Claude Code 用户最早吃到这波红利：工具的壳没大变，壳里的模型换新了，这正是前面说的"工具是驾驭层，模型是发动机"的现场版。默认型号以官方公告为准，但在 2026 年 11 月这个时点，终端流派的天花板又抬高了一截。

第三件：DeepSeek 的调价在 8 月中旬落地，输入、输出、缓存全线上调，涨幅 50% 到 1100%，缓存命中涨幅最大，峰谷定价的规则是"低谷半价"。现价以官方价格页为准。这件事对工具用户的启示很直接：凡是把"用某个模型压成本"当永久前提的方案，都要回头重算一遍账，第 42 章的成本公式照着跑一遍，五分钟的事。价格有涨就有跌，GPT-6 降价和 DeepSeek 调价发生在同一个秋天，成本永远是个动态题。

怎么定位这些价格起伏？给你一个心态上的锚：别追单点价格，盯"能力价格比"的趋势线。单次调价是噪音。三年的趋势是信号——这个趋势在 2026 年依然是"同等能力的价格往下走"，所以长期策略很简单：方案里留出切换余地（Aider 这类模型无关的工具，或者兼容多协议的配置），谁便宜好用就切谁，切的成本要低。锚定趋势的人不会被单次调价吓到，也不会被单次降价诱惑。

##### 共同约定：MCP 与 AGENTS.md

本节开头说"它们开始共享同一套约定"，这里把时间线补齐，MCP（Model Context Protocol，模型上下文协议）是 Anthropic 在 2024 年 11 月发布的开放协议，用来把外部工具和数据源以统一的方式接给模型；后来它交由 Linux 基金会托管，从一家公司的协议变成了行业公共设施，这也是它能被 Claude Code、Cursor、Copilot 等各家普遍支持的关键。你在任何一家工具里学过怎么配 MCP 服务器，到另一家直接复用，学的不是某个产品，是行业通用语。

AGENTS.md 走的是另一条合流路。各家项目记忆文件本来各叫各的（CLAUDE.md、copilot-instructions.md……第三十九章有对照表），AGENTS.md 正在成为通用答案——Codex CLI 的 /init 生成它，越来越多工具直接认它。实操建议：项目约定写一份 AGENTS.md 放根目录，各家的专属补充规则再单独放，一份通吃，换工具不重写。11 月的格局一句话总结：派系还按工作方式分，约定已经按行业合流——选工具的纠结点，从"能不能接 MCP"变成了"接得好不好用"。这是好事：标准的胜利，最终都是用户的胜利。

##### MCP 的第一课：要不要接，怎么接

聊了这么多"约定"，给你 MCP 的第一课。MCP 解决的问题是：智能体想接外部系统：数据库、文档、部署流水线，但每家的接法都不一样。MCP 把"接法"统一了：工具按协议登记一次，各家智能体都能用。你要不要接？一个判断标准：当你发现自己在对话里反复粘贴同一类外部信息（每次都贴工单内容、每次都贴数据库结构），就该接了，粘贴是手动搬运，MCP 是自动管道。

但第一课里最重要的一句是反过来的：不是接得越多越好。每接一个外部系统，你就多开了一条 AI 触碰你数据的通道，第三十九章末尾提醒过的供应链风险，这里再敲一次黑板：装第三方 MCP 服务器前，先查来源、看权限，最小化接入。约定是公共的，钥匙是你自己的。

##### 快照怎么读：三个动作

这份 11 月快照怎么读才有用？给你三个动作。动作一，读增删：对照你脑子里的旧印象，谁进来了（Gemini CLI、Cline、云端并行智能体）、谁升级了（Cursor 的云端产品线、Copilot 的 agent mode），增删清单就是工具圈的"新闻摘要"。动作二，读约定：各家共同点变了什么，MCP 从"某家协议"变成"行业公共设施"、AGENTS.md 从"某家文件"变成"通用答案"，这种合流信号比任何单个产品的发布都重要。动作三，读自己：把第五节那张五维表对着自己的情况走一遍，你的答案跟三个月前比变了吗？变了，就是该调整组合的信号。三个动作二十分钟，快照就从"资讯"变成了"决策依据"。

##### AGENTS.md 里写什么：五件事

AGENTS.md 既然是通用答案，就给你一份"写什么"的清单。一，项目是什么：两三句概述，新会话的第一口上下文，二，怎么跑起来：安装、启动、测试的命令，照抄即可执行的那种。三，约定是什么：命名、目录结构、代码风格，挑最容易违反的五条写。四，禁区在哪：不许动的目录、不许引入的依赖、非目标清单的指针。五，去哪读更多：PRD 和 tasks.md 的路径，一行引用。五件事加起来通常不超过七十行，第 39 章的"70 行记忆文件"原则，在通用文件上照样成立。写完它在两件事上立刻生效：你自己的思路清楚了，换任何一家工具都不用重新自我介绍。

先写 AGENTS.md。

三件大事加两套约定，对选型的落地动作就三条。第一，把你现在用的工具档位和模型配置重新核一遍，发动机换了，油耗曲线也换了。第二，把成本方案从"永久前提"改成"季度复核"。这个秋天的两件事证明，价格前提的保质期以月计。第三，把项目约定收敛到 AGENTS.md——它是"换工具不重写"的那份保单，越早写越早受益。

#### 六、工具会变，方法论不变

:::inline div .quote-line
如果明天所有 AI 编程工具都消失了，你仍然应该保持的三个习惯：先想清楚再动手、每次只做一小步、做完就验证。工具是放大器，方法论是地基。放大器可以替换，地基不能动摇。
:::

回顾 2024 到 2026 年的工具变迁：2024 年 GitHub Copilot 是王者，2025 年 Cursor 取而代之，2026 年 Claude Code 异军突起。每一个新工具出现时，都有人宣称"这次不一样"，但最终发现：<strong>用好新工具的人，恰恰是那些方法论扎实的人</strong>。他们换工具只需要几天适应期，而只学了工具操作的人换一次就要重新学起。

因此，本书建议的学习路径是：先用一个工具（任何一个都行）入门，在实践中体会五大思维原则；当你的方法论足够扎实后，再尝试不同流派的工具，感受它们的设计哲学差异；最终，你会形成自己的工具组合：比如用 Cursor 做日常开发，用 Claude Code 做重构和测试。用 v0 做快速原型。<strong>工具组合因人而异，但方法论是共通的</strong>。最后送你一句好用的账：时间花在"怎么验收"上，比花在"哪个最强"上值钱得多。

先用一个。

把 quote 里那三个习惯再操作化一遍，因为它们是本章所有工具的"公共接口"。先想清楚再动手：对应第 40 章的五要素卡，任何工具都吃得进。每次只做一小步：对应"只做当前一步"的铁律，从云端 Builder 到终端智能体全都适用，小步在哪个流派都不吃亏。做完就验证：对应验收标准加第 45 章的测试，工具越自主，这一步越不能省。你会发现一个规律：方法论扎实的人，换任何新工具的第一天就能产出合格的东西；工具依赖者换一次就归零。差距不在手，在脑子里的流程。

#### 七、选型决策树：五个问题定工具

前面的表格给了维度，这一节把它们串成一棵能走通的决策树。五个问题按顺序问，每个答案都砍掉一批选项，问到第五个，通常只剩一两个候选，整个过程不超过五分钟。

1. <strong>要做的事，在浏览器里就能完成吗？</strong>纯前端页面、一次性演示、给别人看的原型，能，云端 Builder 入场，后面四问不用答了。要接真实数据、要长期维护——往下走。
2. <strong>你和终端熟吗？</strong>会开命令行、会 cd、看到报错不心慌，不熟就留在 IDE 流派（Cursor、Trae、Copilot、国产各家），终端流派先收藏，练熟了再回来。
3. <strong>任务是"边想边做"还是"成批明确"？</strong>探索性开发，用 IDE 内智能体或手边的终端智能体；一串定义清楚的工单，丢给云端并行智能体排队跑。
4. <strong>要接基础设施吗？</strong>要接 MCP、hooks、项目记忆文件，或者要进 CI/CD 流水线，优先生态最全的那几家；暂时用不上，这条不设限。
5. <strong>预算形状是什么？</strong>用量稳定的，订阅档舒服；忽高忽低的，按量计费或自带 Key 的工具更划算，账怎么算，第 42 章讲过。

拿两个例子走一遍。例一：想给自己做个"记账加统计"的小网页，没写过代码，电脑是用了五年的轻薄本。第一问：网页，能，云端 Builder，完事，总共十秒。例二：公司内网的老系统要批量改接口，你写了十年代码，公司要求数据不出内网。第一问：不能，过；第二问：终端熟，过；第三问：成批明确，终端或云端并行；第四问：要进 CI，选生态全的终端智能体；第五问：公司报销，订阅档。两分钟，选型完成，还能顺手写出选型理由向老板汇报。

决策树不是一次性问卷，是随项目阶段重走的路标。原型期你在第一问就下车。三个月后项目转正，你会一路走到第四问，这不是换信仰，是项目长大了。每三个月重走一遍，跟本章开头那句"快照会过时"是同一个道理：环境变了，答案就变，重走就是刷新。顺手把它做成手机备忘录模板：五行，一行一问，答案跟在后面——通勤路上就能重走一遍，这也是一本手机课该有的用法。

五问之外，还有一个隐藏问题值得单独说：团队还是单人？单人选型看"顺不顺手"，团队选型看"好不好推广"，上手门槛、管理后台、合规配套、统一计费，这些维度团队场景的权重远高于个人。一个人用得好好的工具，推给十个人可能鸡飞狗跳；反之亦然。如果你是"给团队选工具的人"，决策树的每个答案都要在"我喜欢"和"大家好用"之间过一道秤。

还有一种情况：五问走完，剩下两个候选，还是定不下来。这时候别再纠结，用"两周试用法"收官，两个各跑一个真实小任务，看三个体验：哪个的计划展示让你更放心？哪个的报错解释你读得懂？哪个的确认节奏不让你烦？两周后自然有答案。还打平？那就随便选一个，先用起来，纠结的时间成本，早就超过两个工具的能力差距了。

先跑起来。

读表三个提醒：强项弱项都是"相对赛道"，Cursor 的弱项放到 IDE 赛道里可能就是平均线；价格一栏全是"模式"不是"报价"，下单前官网核对；"适合谁"是最重要的一列：工具没有最好，只有对路。云端 Builder 三家（v0、Bolt、Replit Agent）没有进表，因为它们是"阶段工具"：原型期谁顺手用谁，验证完就迁走，不值得长期绑定。这张表本身也要维护：每季度更新快照时顺手核一遍，弱项被修掉的、强项被反超的，动笔改，表是活的，跟你的决策树一起长大。

从表到行动只要三步。第一步，按"适合谁"那一列圈出两个候选，最多两个，多了又是选择瘫痪。第二步，给每个候选半小时的"半天试用法"（第二节教过）：同一个真实小任务各跑一遍，比跟手感、理解力、报错解释。第三步，胜者当场装上，败者写三行笔记存档——下次快照刷新时，这份笔记就是你自己的档案卡。表给你地图，试给你手感，笔记给你记忆，三样凑齐，选型就从玄学变成了流程。

##### 两份"上手一周"计划

给最常见的两类读者各排一份一周计划。Cursor 周：周一，装好并打开现有项目，只用 Tab 补全，周二周三，Tab 加行内编辑，顺手把项目规则文件的底稿写了；周四，开 Agent 给一个两文件的小任务，完整审一遍 diff；周五，开 Agent 做一个三文件以上的任务，体会计划和验收；周末，复盘记录"哪些活值得交出去"。Claude Code 周：周一，装好，让它讲一遍项目结构；周二，一个小任务（补测试补注释），逐条看它的计划；周三，写好 CLAUDE.md 再跑同类任务，对比差别；周四，一个中型重构任务，练习放行与驳回；周末，把一个高频动作固化成自定义命令（以官方文档为准）。两份计划各花每天半小时，一周后你就不是"听说过"。一周后你就是"用过了"。

一周计划最常见的三个失败点，提前打预防针。失败点一：第一天就挑战高难度：用没配好规则文件的工具做复杂任务，产出拉胯，然后得出"工具不行"的结论。按计划走，规则文件是第四天才动，别提前跳步。失败点二：全程不审改动，攒了一周问题周五一起炸：审阅是每天的动作，不是周末大扫除。失败点三：只跑计划不记笔记——每天三行字记"今天它哪里让我惊喜、哪里让我翻车"，周末复盘全靠它。三个失败点的共同解药也简单：把计划当药，按时按量，别自行加量。

给零基础读者再补第三份计划，"云端周"，它和前两份不冲突，是排在最前面的预备周：第一天，注册一个云端 Builder，一句话起一个项目；第二天，对着预览连提五轮修改，感受"说清需求"和"产出质量"的关系；第三天，把一个想法按五要素加工后再跑一遍，对比上一次的差别；第四天，把项目导出到本地存档；第五天，写一页纸 PRD 决定这个项目还做不做；周末，回答一个问题：我下一步想进 IDE 流派还是先在云端多玩几个？七天下来，你对"AI 能做什么"的判断就不是听来的，是自己摸出来的。

#### 九、给三类用户的工具组合

单工具是入门，组合是常态。按人群给三套组合方案，每套说清四件事：主力是谁、副手是谁、预算形态、第一个月干什么。组合的最小单位是"一主一副"：一个日常工具加一个特定场景工具，两件套就够大多数人用一年；超过三件，每多一件都在增加切换成本，先问自己压不压得住。

##### 1. 零基础体验派：先造出来，再谈工程

主力：云端 Builder（Bolt 或 v0）；副手：手机上的通用 AI 助手，用来讨论需求；预算：免费档起步，够用再升；第一个月：用云端 Builder 造三个小东西，个人主页、投票页、记账页，每个都按第 40 章写五要素卡。这个阶段唯一的目标是建立"我能造东西"的手感：别碰终端，别管流派之争，别急着付费。

这个人群的账最好算，给你一个学生党的月度样本：免费档跑完三个小项目，一分没花；觉得不够用了，升一个入门订阅档，一顿饭钱换一个月的畅快探索；模型层用各家自带的默认配置，不用单独掏 Key。整套开销控制在"一杯奶茶一周"的量级——真正的投入是你的十几个小时，而那十几小时买来的"我能做东西"的底气，是你这个阶段最值钱的资产。

升级信号要认得：当你在云端工具里说"这个逻辑怎么又不对"的次数超过"这个样式再改改"，说明你需要真正的开发环境了。这时候迁到 Trae 或 Cursor，前面的五要素卡和 backlog 全都带得走，一份都不浪费。

##### 2. 有基础的进阶派：一个主力 IDE 加一个终端副手

主力：Cursor 3 或 Trae，承包日常开发；副手：Claude Code（或先用 Gemini CLI 试水），承包重构、批量修改和测试；模型：按第 42 章的四问决策法配，日常用性价比款，关键设计用旗舰款；预算：一个订阅档为主，按量为辅。第一个月：主力做日常，副手完成一次真重构，把 AGENTS.md 和记忆文件写起来。

这个人群最常见的坑是"来回横跳"：两个工具各用三天，哪个都是半桶水。给自己立个规矩：同一个项目前两个月只用一套组合。磨合出习惯再谈换。工具的产出质量跟你的熟练度强相关，熟练度只能靠连续使用攒出来。成本账也给你一笔：一个主力订阅加副手的按量或免费额度，是这个人群的常见形态；每月定一个总额，超额的第一个信号不是钱包疼，是你开始为"怎么省额度"而改变工作方式，那时候该做的是换档位或换方案，而不是委屈自己的用法。

##### 3. 认真派与小团队：组合拳加基础设施

主力：IDE 智能体做日常，终端智能体做重构和 CI；副手：云端并行智能体跑工单队列；基础设施：MCP 接问题跟踪和部署流水线，AGENTS.md 统一项目约定，hooks 卡质量关（第 45 章）；预算：按人头订阅加关键流程按量。第一个月：把"需求（第 40 章）、上下文（第 39 章）、编码、验收（第 45 章）"的全链路跑通一次，把每个环节用什么工具钉死成文档。

团队和个人最大的差别是"约定值钱"：五个人五个用法，协作成本指数级上升。宁可开半小时会统一工作流，也别让大家各自为战。统一的那套不必是最优的，一致比最优重要。另外团队的订阅盘点要定成制度：每个季度查一次用量，三个月没动过的席位，退。

团队落地给三步，照着走不踩坑。第一步，定"最小共识"：统一主力工具、统一记忆文件、统一验收流程，三样就够，别一上来统一十件事。第二步，把共识写成文档：一页纸，放进项目仓库，新人入职第一天读，口头共识撑不过三个月。第三步，留"例外通道"：谁有更好的用法，走一个"先试点两周、复盘后推广"的流程，共识要硬，通道要软，两头都占的组合才活得久。

收个尾之前，给组合立三条禁忌。禁忌一：一个项目换三套工具，产出风格不一，验收标准混乱，谁都没学熟；一个项目一套组合，是铁律。禁忌二：为组合而组合：三件事的小项目配"主力加副手加并行"，纯属排场大于实效；组合的规模跟着项目走。禁忌三：把组合当信仰：Cursor 用户嘲笑终端党、终端党嘲笑云端党的画面，2026 年还天天上演；流派是分工不是阵营，你的组合该服务于你的项目，不该服务于你的身份认同。

组合还会随阶段演进，拿进阶派举个完整的例子。项目起步期：主力 IDE 单打独斗，副产品是不定期开终端跑一次测试。项目成长期：终端副手转正，每周固定承包一次重构和批量修改，云端并行智能体开始接工单。项目稳定期：你的角色进一步后移：写需求、审验收。编码大头交给组合，你盯着全链路。回头看，你的"工具组合"其实记录着你自己的成长：从操作者到指挥者，工具只是这条路上的里程碑。最后仍然要收那句尾：组合是拿来干活的，不是拿来收藏的：工具栏里躺着六个付费订阅、每个都用三天的状态，是这个人群的通病；工具组合像衣柜，按场合搭配，但衣柜本身要定期清。

#### 十、演进趋势与预判（带保质期）

按惯例先声明：以下是基于 2026 年 11 月快照的推演，保质期半年，打脸不赔。预判的意义不是让你照做，是让你知道往哪个方向留神。

- <strong>派系边界继续溶解</strong>：编辑器做终端、终端做界面、云端做本地导出："工作方式"仍是分类主轴，但单一形态的工具会越来越少，"全家桶化"是各家共同的方向。
- <strong>约定层进一步收拢</strong>：MCP、AGENTS.md、子代理、hooks 会成为所有工具的标配词汇表：竞争焦点从"有没有"变成"接得顺不顺"。
- <strong>模型价格带整体下探但不再无限便宜</strong>：GPT-6 定价约为上代一半、DeepSeek 结束促销期，一降一涨是同一个信号，成本进入"精算时代"，工具层拼的是"怎么把额度用得值"。
- <strong>验证成为新瓶颈</strong>：当生成足够便宜，瓶颈从"写代码"移到"验代码"，测试、验收、review 的工具和方法（第 45 章）会吃掉下一波创新。
- <strong>多智能体分工常态化</strong>：主智能体加子代理加云端并行的"工头模式"从尝鲜变成日常，需要的是会排工单的人，第 40 章的需求拆解，就是排工单的手艺。

还有一个不敢写进清单、但值得你留意的方向：手机端的 AI 编程。本书毕竟是本手机课。云端 Builder 加手机浏览器，已经能完成"描述、预览、迭代"的闭环；第十三章讲的手机遥控电脑工作流，也在把"用手机指挥 AI 干活"变成日常。半年后再看这一条，或许就不用"或许"了。

趋势之下还有个绕不开的现象：工具同质化。各家都有 Agent、都有补全、都接 MCP，参数表越来越像：这时候选什么？三样东西在参数表上看不见，值得你亲自试：一是"确认点的设计"，它的计划展示和放行方式让你舒服吗；二是"失败的姿态"，出错时它是给你清晰的解释还是一串日志；三是"上下文的诚实度"，它会不会明确告诉你"我缺这个信息"。同质化时代的差异，藏在这些体验细节里，这也是为什么本节开头说"信你的实测"，测评文章量不出手感。

面对趋势的个人策略就一句话：往方法论上压注，别往工具上压注。工具会换皮。方法论保值——这句话第六节说过。预判部分再说一遍，因为半年后你会想起它。三类人群的应对各给一句：零基础派，趋势与你无关，把云端 Builder 玩熟就是最大的趋势；进阶派，盯住"约定层"的演进，MCP 和 AGENTS.md 的每一步变化都值得花半小时了解；认真派，把"验证瓶颈"当成排期依据。下一阶段的预算和培训，往测试和验收上倾斜。

要是预判打脸了呢？打脸就打脸——季度复盘快照的时候，把这一节拿出来逐条核对，错了的改掉，对了的打个勾。预判的价值从来不是"押中考题"，是给你一个可修改的框架：没有框架的人面对变化只能被动挨打，有框架的人错了也知道错在哪一格。这也是全书反复出现的态度：结论可以错，方法不能丢。

#### 十一、FAQ：关于工具的十个真问题

<strong>问：零基础直接上 Cursor 行不行？还是必须先从云端 Builder 开始？</strong>

答：行，但容易劝退：不是工具难，是你同时要学编程、学工具、学方法论三件事，全挤在一个界面里。云端 Builder 先建立信心，再上来学 IDE，每一步只新增一样东西，不容易半途而废。

<strong>问：这些工具会不会让我失业？会不会让我不用学编程？</strong>

答：它替代的是打字量，不是判断力。需求拆解、验收标准、架构取舍——这些反而更值钱了（第 37 到 40 章整篇都在讲这个）。"不用学编程"的准确说法是"学编程的重心变了"：从记语法，变成学表达和验收。免费额度的问题顺手答了：学习阶段够用，干活阶段悬，额度规则各家常变，以官网为准，学到一半被限额，通常说明该认真算一次账了。

<strong>问：国产工具和海外工具差距大吗？要不要硬上海外那几家？</strong>

答：分场景。中文场景、国内网络、合规部署，国产占优；生态成熟度、Agent 自主性上限，海外第一梯队仍有优势：但差距在缩小，而且模型层是流动的（Aider 这类工具谁便宜接谁）。别信测评站，信你的实测：同一个真实任务，两个工具各跑一遍，答案自己会说话。

<strong>问：要不要为了某个新模型换工具？</strong>

答：先看这个工具能不能换模型。Aider、Cline 这类"模型无关"的，换模型不用换工具；绑死单一模型的，换模型等于换工具，成本高：选型时就要想清楚这一层。

<strong>问：公司不让把代码传到云端，怎么办？</strong>

答：三条路：选支持本地或私有化部署的方案；用本地模型（第 42 章末尾讲过）；或只用补全类功能，代码不出库。先问清公司的红线在哪一条，再选工具——顺序别反了。顺手记一条通用判断：红线管的是"代码和数据去哪"，不是"AI 能不能参与"，多数公司的禁令比传闻宽松，问清楚再自我设限。

<strong>问：同一件事，两个工具给出不一样的答案，信谁的？</strong>

答：都别信，信验收。跑一下、测一下，谁的对用谁的。分歧本身是线索：两个都"对"说明需求有歧义，回第 40 章补规格。

<strong>问：Cursor 3 的 Agent 模式反超了 Tab，那 Tab 补全可以扔了？</strong>

答：不是反超了就取代了。补全管"手边的小步"，Agent 管"整段任务"，分工不同。快照数据告诉你的是"大家把更多时间花在哪"，不是"你该关掉哪个"，改一行字用 Agent，反而慢。

<strong>问：这一章的工具都在讲电脑，我天天在外跑，手机上能干嘛？</strong>

答：三件事在手机上已经能干：云端 Builder 的描述与预览（第四节讲过闭环）、用通用 AI 助手讨论需求写五要素卡、WorkBuddy 这类办公助手的轻自动化发起。真到写代码那一步，手机遥控电脑（第十三章）或回来用电脑即可。手机是 AI 编程的"指挥席"，不一定要是"操作台"。

#### 十二、三十天熟手计划：从"会用"到"用好"

本章讲了流派、深评、决策树、组合，最后给你一份三十天的熟手计划：把工具知识变成肌肉记忆。为什么是三十天？四个星期，四个里程碑，每天半小时到一小时，强度小到不会跟生活抢时间；四周下来，"每天摸一次工具"本身就成了习惯，而习惯恰好是工具熟的真正原因。四周四个主题，每周围绕一套组合。

- <strong>第一周：单工具打底</strong>。按第八节的上手一周计划走完你的主力工具，周末产出：一份自己的"什么时候交任务、什么时候自己动手"清单。
- <strong>第二周：方法论接入</strong>。把第 40 章的三张模板卡用进主力工具，每个任务都过五要素、发五段式指令，周末产出：一份磨过手的 AGENTS.md。
- <strong>第三周：加一个副手</strong>。第二流派进场（通常是终端或云端），给它一类明确的分工（重构或原型），周末产出：一份双工具分工表。
- <strong>第四周：全链路演练</strong>。拿一个真实小项目，从需求卡到验收全流程走一遍，涉及哪个环节就用对应环节的工具，周末产出：一份带复盘的项目总结。

三十天后的验收标准也给你：给你一个从没做过的东西，你能在十分钟内说出"我用哪套组合、分几步、每步怎么验收"，能，你就是熟手了。熟手和新手的差距从来不在掌握的工具数量，而在"接到活之后的第一反应"：新手想"用什么工具"，熟手想"活怎么拆"。第四周的复盘模板也一并给你，三行：这个项目哪一步最顺（那是你的组合在发力）、哪一步返工最多（那是你的短板所在）、下个项目改哪一处（一次只改一处）。三个月后翻出来看，你的进步会自己排队站好：而那份复盘，就是你和这一章快照的合影。

这份计划还有三个变体，对号入座。学生版：电脑是机房公用机，把第二周换成云端 Builder 加手机备忘录的组合，方法论照练，工具可以租借。上班族版：只有晚上一小时，把每周任务拆成五个二十分钟的小块，进度慢一半没关系，链条不断就行。重度版：本来就有每天写代码的习惯：把四周压成两周。重点放在第二、三周的"方法论接入"和"分工表"，那两步对老手最有增量。

这份计划也顺便回答了本章最开头埋的那个问题，半年后快照过时了怎么办？过时的快照留给按季刷新的例行公事，而三十天练出来的"接到活就拆活"的反应，不会过时，带着你的组合去第 44 章跑真项目吧——工具的全部意义，在真项目里才显影。

<strong>问：半年后这章过时了，我自己怎么更新快照？</strong>

答：三步：看各家官方博客和更新日志（一手信息最可靠）；把你常用的两三个工具各跑一次更新说明里的新功能；重走第七节的决策树。把"更新快照"变成每季度的例行公事，你就永远不怕过时：这正是本章开头的承诺，闭环了。

<strong>问：我已经有了一套用顺手的组合，看到新工具发布还是忍不住想试，怎么克制？</strong>

答：给它立个"试用预算"：每月留一个下午，只试新工具，其余时间锁死主力组合。试完写三行结论存档。这样既不亏待好奇心，也不让新鲜感打断正事——好奇心要喂，但不能放养。
