الفرع (Branch)<strong>: خط تطوير مستقل منفصل عن المسار الرئيسي. على سبيل المثال، إذا أردت إضافة ميزة جديدة، يمكنك فتح فرع للتطوير المنفصل، ثم الدمج مع المسار الرئيسي بعد الانتهاء، دون التأثير على الآخرين.</strong>الاستنساخ (Clone)

#### ثالثًا: المفاهيم والوظائف الأساسية في GitHub

##### 📁 مفاهيم أساسية

: Push هو رفع الكود المحلي إلى GitHub السحابية، و Pull هو تنزيل أحدث كود من GitHub إلى المحلي. هذان هما الإجراءان الأساسيان لمزامنة الكود أثناء عمل الفريق.

- <strong>طلب الدمج (Pull Request، اختصارًا PR)</strong>: عندما تنتهي من تعديل الكود على فرع وتريد دمجه في الفرع الرئيسي، تطلق PR ليراجع أعضاء الفريق الكود قبل الدمج. هذه هي آلية التعاون الأساسية في GitHub.
- <strong>المسألة (Issue)</strong>: تُستخدم لتسجيل الأخطاء وطلبات الميزات ومواضيع النقاش. كل Issue مثل منشور نقاش، يمكن تعيين مسؤول له ووضع علامات.
- <strong>Fork</strong>: نسخ مستودع شخص آخر إلى حسابك، يمكنك التعديل بحرية على نسختك دون التأثير على المستودع الأصلي. بعد الانتهاء يمكنك إرسال PR للمؤلف الأصلي لطلب دمج تحسيناتك.
- <strong>🛠️ الوظائف الأساسية</strong>ما يقدمه GitHub ليس مجرد تخزين للأكواد، بل يشمل أيضًا:
- <strong>تحكم الإصدارات</strong>: تسجيل تاريخ كل تغيير في الكود، والعودة في أي وقت إلى آخر إصدار سليم عند تلف الكود.
- <strong>تعاون الفريق</strong>: دعم التطوير المتوازي لنفس المشروع من عدة مستخدمين، دون الكتابة فوق بعضهم البعض أو التعارض.
- <strong>تتبع المشكلات</strong>: استخدام Issue لتسجيل الأخطاء وطلبات الميزات، لتسهيل متابعة الفريق.
- <strong>إدارة المشاريع</strong>: تكامل أدوات إدارة مثل المهام وألواح المشروع (Projects)، أي ما يعادل Trello خفيف مدمج.

##### 🛠️ الوظائف الأساسية

: عبر

- <strong>GitHub Actions</strong>لتنفيذ التجميع والاختبار والتعبئة والنشر تلقائيًا بعد إرسال الكود، وهي أداة أساسية في "CI/CD (التكامل المستمر/النشر المستمر)" الحديث.
- <strong>إدارة الوثائق</strong>: README يقدم المشروع، و Wiki يخزن البنية المعمارية التفصيلية ومعايير التطوير، ويمكن لـ Pages استضافة مواقع ثابتة مباشرة.
- <strong>استضافة الأكواد وعرضها</strong>: لكل مستودع صفحة ويب جميلة العرض، مع دعم تلوين الصيغة، وهي "واجهة" أعمالك التقنية.
- <strong>مجتمع مفتوح المصدر</strong>: يمكنك Star (مفضلة) المشاريع التي تعجبك، و Watch (متابعة) مستجدات المشاريع، و Follow (متابعة) المطورين، والمشاركة في التعاون مفتوح المصدر عالميًا.
- <strong>رابعًا: التسجيل والبدء — أنشئ أول مستودع لك في خمس دقائق</strong>📝 تسجيل حساب<strong>زر</strong>github.com
- <strong>، وانقر على "Sign up".</strong>املأ البريد الإلكتروني، واضبط كلمة المرور واسم المستخدم (سيظهر اسم المستخدم في عنوان صفحتك الشخصية، يُنصح بالإنجليزية، مثل
- <strong>github.com/yourname</strong>).
- <strong>أكمل التحقق من البريد الإلكتروني والتحقق البشري.</strong>اختر الخطة المجانية (Free)، وهي كافية تمامًا للمستخدمين الأفراد.

#### رابعًا: التسجيل والبدء — أنشئ أول مستودع لك في خمس دقائق

2. اكتب وصفًا موجزًا (Description) ليعرف الآخرون ما يفعله هذا المستودع.<code class="bg-gray-100 dark:bg-gray-800 px-1 rounded">اختر عام (Public) أو خاص (Private). المستودعات العامة يراها الجميع، والخاصة يراها أنت والمتعاونون فقط. الحسابات المجانية تدعم أيضًا مستودعات خاصة غير محدودة.</code>حدد "Add a README file" — README هو "كتيب التعليمات" للمشروع، ويُنصح بوجوده في كل مستودع.
3. انقر على "Create repository"، وقد وُلد أول مستودع GitHub لك!

#### خامسًا: سير العمل الأساسي — من المحلي إلى السحابة

: رفع الالتزامات المحلية إلى GitHub السحابية، ليتمكن الآخرون من رؤيتها.<strong>git pull</strong>: قبل بدء العمل، اسحب أحدث كود من السحابة لضمان مزامنة المحلي مع بقية الفريق.

1. <strong>للمبتدئين، تذكر هذه القاعدة:</strong>"اسحب أولًا ثم عدّل، بعد التعديل add، و commit مع رسالة، وأخيرًا push"
2. <strong>. اكتسب هذه العادة ولن يختلط عمل الفريق.</strong>سادسًا: سير عمل تعاون الفريق — كيف يعمل Pull Request
3. <strong>أقوى جانب في GitHub هو آلية التعاون. سير عمل التعاون الفريقي النموذجي هو:</strong>فتح فرع
4. <strong>: افتح فرعًا جديدًا من الفرع الرئيسي (يُسمى عادة main أو master)، مثل</strong>feature/login
5. <strong>، وطوّر الميزة الجديدة على هذا الفرع.</strong>التطوير والالتزام

: اكتب الكود على الفرع الجديد، و commit عدة مرات لتسجيل التقدم.<strong>الدفع إلى GitHub</strong>: ارفع الفرع إلى المستودع السحابي.

#### سادسًا: سير عمل تعاون الفريق — كيف يعمل Pull Request

: أطلق PR على صفحة GitHub، لطلب دمج فرعك في الفرع الرئيسي. اكتب بوضوح ما الذي تغير في هذا PR ولماذا.

1. <strong>مراجعة الكود (Code Review)</strong>: يطّلع أعضاء الفريق على كودك ويطرحون آراء أو اقتراحات للتعديل. يمكنك الاستمرار في commit بناءً على التغذية الراجعة، وسيُحدَّث PR تلقائيًا.<code class="bg-gray-100 dark:bg-gray-800 px-1 rounded">الدمج</code>: بعد اجتياز المراجعة، انقر "Merge" لدمج الكود في الفرع الرئيسي. وقد دخلت مساهمتك المشروع رسميًا!
2. <strong>يضمن هذا التدفق أن</strong>أي كود يدخل الفرع الرئيسي يمر بالمراجعة
3. <strong>، مما يقلل بشكل كبير من احتمال الخطأ. المشاريع مفتوحة المصدر تستخدم أيضًا هذه الآلية لقبول مساهمات الغرباء حول العالم — يمكنك تمامًا تقديم PR في مشروع مفتوح المصدر معروف، وبعد قبوله تصبح مساهمًا في هذا المشروع.</strong>سابعًا: سيناريوهات التطبيق النموذجية لـ GitHub
4. <strong>🎓 مسابقات الطلاب ومشاريع المقررات</strong>يستخدم طلاب علوم الحاسوب GitHub في مسابقات ACM وهاكاثون ومشاريع التخرج. فهو منصة تعاون فريقي ونافذة عرض للأعمال — يمكن لجنة التحكيم أن تطّلع مباشرة على مستودعك لتفهم جودة الكود وعملية التعاون. كثير من الشركات تطلب أيضًا إرفاق صفحة GitHub الرئيسية عند التوظيف، كدليل على القدرة التقنية.
5. <strong>📚 قاعدة المعرفة الشخصية واستضافة الملاحظات</strong>غير المبرمجين يستطيعون استخدام GitHub أيضًا. كثيرون يستخدمونه لاستضافة ملاحظات التعلم والمدونات التقنية (مع GitHub Pages يمكن إنشاء موقع مجاني) والكتب الإلكترونية. الكتابة بتنسيق Markdown + إدارة الإصدارات بـ Git + النسخ الاحتياطي السحابي، ثلاثة في واحد.
6. <strong>🌐 المشاركة في المشاريع مفتوحة المصدر</strong>GitHub هو المعقل الأساسي لحركة مفتوح المصدر عالميًا. يمكنك Fork المشاريع التي تعجبك، وتعديلها ثم إرسال PR لرد الجميل للمجتمع؛ أو ببساطة Star للمشاريع الجيدة ومتابعة التحديثات. المشاركة في مفتوح المصدر طريق ممتاز لتحسين التقنية وبناء السمعة.

🤖 النشر الآلي و CI/CD<strong>بمساعدة GitHub Actions، يمكن تحقيق تدفق آلي بالكامل "دفع الكود، اختبار تلقائي + نشر تلقائي على الخادم". هكذا يُبنى كثير من المدونات الشخصية ومواقع الوثائق، تكتب المقال وتدفعها فيتحدث الموقع تلقائيًا.</strong>💾 النسخ الاحتياطي للكود والمزامنة بين الأجهزة

#### ثامنًا: نصائح للمبتدئين

- <strong>تقدم بحزمة طالب GitHub</strong>: بعد مصادقة الطلاب يمكنك الحصول مجانًا على حصص كبيرة من الأدوات والخدمات المدفوعة (Copilot، أسماء النطاقات، الخدمات السحابية، إلخ)، بقيمة آلاف الدولارات.
- <strong>تذكير أمني</strong>لا ترفع أبدًا معلومات حساسة مثل كلمات المرور ومفاتيح API وسلاسل اتصال قواعد البيانات إلى GitHub، خاصة في المستودعات العامة — بمجرد التسريب ستلتقطها برامج الزحف فورًا والعواقب وخيمة.
- <strong>إذا رفعت معلومات حساسة بالخطأ، فحذف الملف لا يكفي (لأنها لا تزال في السجل التاريخي)، استخدم</strong>git filter-branch
- <strong>أو أدوات متخصصة لتنظيف التاريخ، وغيّر فورًا المفاتيح المسربة.</strong>المستودعات الخاصة ليست آمنة تمامًا أيضًا، يُفضل إدارة المعلومات الحساسة بمتغيرات البيئة، ولا تدخلها في مستودع الكود.
- <strong>ملاحظات للوصول إلى GitHub من داخل الصين</strong>قد يكون الوصول إلى GitHub من داخل الصين غير مستقر أحيانًا، فقد لا يفتح أو يكون الاستنساخ بطيئًا. يمكنك تجربة: ① استخدام مواقع مرآة محلية (مثل GitClone وghproxy) لتسريع الاستنساخ؛ ② تكوين Hosts أو استخدام وكيل؛ ③ إذا كان التعاون موجّهًا أساسًا للداخل، يمكنك أيضًا التفكير في البديل الصيني
- <strong>Gitee (مايون)</strong>، بوظائف مماثلة وسرعة وصول عالية. كثير من الفرق تستضيف على GitHub و Gitee في الوقت ذاته، لجمع الفوائد الدولية والسرعة المحلية.
