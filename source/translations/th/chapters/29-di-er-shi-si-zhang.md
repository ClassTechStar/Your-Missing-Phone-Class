### บทที่ 24: เจาะลึกสิทธิ์ Root และกุญแจ BL

{class="chapter-intro mb-4"}
บทนี้เป็นการขยายต่อจากเนื้อหาบทที่ 20 อย่างลึกซึ้ง เหมาะกับคนที่อยากเข้าใจกลไกชั้นล่างของมือถืออย่างแท้จริง หรือแม้แต่อยากลองแฟลชรอมดู โปรดทราบว่าการทำงานเหล่านี้มีความเสี่ยงอยู่บ้าง โปรดดำเนินการด้วยความระมัดระวัง

#### หนึ่ง เข้าใจ Bootloader อย่างลึกซึ้ง

Bootloader คือโปรแกรมแรกที่รันเมื่อมือถือเปิดเครื่อง หน้าที่ของมันคือเริ่มต้นฮาร์ดแวร์และโหลดเคอร์เนลของระบบปฏิบัติการ จะมอง Bootloader เป็น "ยามเฝ้าประตู" ของมือถือก็ได้

##### หลักการทำงานของ BL Lock:

- <strong>การตรวจสอบลายเซ็น</strong>: BL Lock จะตรวจสอบลายเซ็นดิจิทัลของอิมเมจบูต มีแต่ระบบที่ผู้ผลิตลงลายเซ็นเท่านั้นถึงจะบูตได้
- <strong>กันดาวน์เกรด</strong>: กันผู้ใช้แฟลชระบบรุ่นเก่าลงไปเพื่อเจาะช่องโหว่ที่รู้จักแล้ว
- <strong>ปกป้องข้อมูล</strong>: แม้แฟลชระบบใหม่ลงไป ถ้าไม่มีรหัสผ่านบัญชีเดิมก็เข้าถึงข้อมูลผู้ใช้ไม่ได้

##### 🔐 การจัดเก็บและยืนยันระดับฮาร์ดแวร์

สถานะการล็อก BL (Locked/Unlocked) และ Public Key ของผู้ผลิต มักถูกจัดเก็บไว้ในพื้นที่ฮาร์ดแวร์ที่ได้รับการปกป้อง (เช่น พาร์ติชัน devinfo ของ Qualcomm, eFuse หรือพาร์ติชัน RPMB) เพื่อป้องกันการถูกดัดแปลงด้วยซอฟต์แวร์ ในแต่ละครั้งที่บูต Bootloader จะอ่านสถานะจากพื้นที่ปลอดภัยนี้ และใช้เป็นเกณฑ์ในการตัดสินใจว่าจะดำเนินการตรวจสอบลายเซ็นแบบเข้มงวดหรือไม่

##### 🔏 การตรวจสอบลายเซ็นดิจิทัล

เมื่อผู้ผลิตเผยแพร่อัปเดตระบบหรืออิมเมจ จะมีการเซ็นชื่อด้วย Private Key ของตนเอง เมื่ออุปกรณ์บูต Bootloader จะใช้ Public Key ในตัวเพื่อตรวจสอบอิมเมจระบบ (เช่น boot.img, recovery.img) วิธีการทำงานคือ:

1. คำนวณค่าแฮชของอิมเมจระบบใหม่อีกครั้ง
2. ใช้ Public Key ถอดรหัสลายเซ็นที่มากับอิมเมจ เพื่อให้ได้ค่าแฮชออกมาหนึ่งค่า
3. เปรียบเทียบค่าแฮชทั้งสองค่า หากตรงกันแสดงว่าผ่านการตรวจสอบ ซึ่งจะรับประกันได้ว่าอิมเมจระบบไม่ถูกดัดแปลงโดยบุคคลที่สาม

##### 🔗 ห่วงโซ่การบูตที่ปลอดภัย

การล็อก BL คือวงแรกของห่วงโซ่การบูตที่ปลอดภัยทั้งหมด เมื่อผ่านการตรวจสอบแล้ว จึงจะโหลดและดำเนินการโปรแกรมบูตในขั้นตอนถัดไป (เช่น Kernel) เพื่อให้มั่นใจในความน่าเชื่อถือของสภาพแวดล้อมการบูตระบบทีละขั้นตอน

##### 📊 ล็อก vs ปลดล็อก: ผลกระทบสองด้านของการล็อก BL

เพื่อให้เข้าใจข้อดีและข้อเสียของการล็อก BL ได้ชัดเจนยิ่งขึ้น เราจะใช้ตารางเปรียบเทียบเพื่อแสดงความแตกต่างใน 5 มิติหลัก:

#### 2. ขั้นตอนปลดล็อก BL โดยละเอียด (ยกตัวอย่าง Xiaomi)

1. <strong>4. เริ่มต้นแฟลชรอม</strong>รีเฟรชเครื่องใช่ชี้ให้โทรศัพท์มือถือติดตั้งใหม่ของดำเนินการระบบ ทั่วไปของรีเฟรชเครื่องประเภท:
2. <strong>รีเฟรชทางการROM</strong>:ติดตั้งทางการระบบ, สำหรับกู้ภัยอิฐหรือการดาวน์เกรด
3. <strong>รีเฟรชบุคคลที่สามRecovery</strong>:เหมือนTWRP, สำหรับสำรองข้อมูลกู้คืน, รีเฟรชเข้าบุคคลที่สามROM
4. <strong>รีเฟรชบุคคลที่สามROM</strong>:เหมือนLineageOS, Pixel Experienceชั้น, ประสบการณ์ต่างกันของระบบ

#### 3. วิธี Root หลายแบบ

- <strong>รีเฟรชเครื่องมีความเสี่ยง, ดำเนินการต้องการระมัดระวัง อาจทำให้:</strong>โทรศัพท์มือถือเปลี่ยนอิฐ(ไม่มีวิธีเปิดเครื่อง)
- <strong>หมดประกัน</strong>ข้อมูลทิ้งเสีย
- <strong>จ่ายเงินการทำงานผิดปกติ</strong>รีเฟรชเครื่องหน้าต้องทำดีเสร็จทั้งหมดสำรองข้อมูล, ระมัดระวังละเอียดอ่านอ่านสอนกระบวนการ, ยืนยันเครื่องรูปแบบและเวอร์ชันจับคู่

#### 5. Samsung Knox: ราคาที่ไม่สามารถย้อนกลับได้ของการปลดล็อก BL

ต่างจากผู้ผลิต Android รายอื่น กลไกการปลดล็อก BL ของโทรศัพท์ Samsung มีดีไซน์ "ฟิวส์ขาด" ที่เป็นเอกลักษณ์:<strong>สำหรับโทรศัพท์ Samsung การปลดล็อกจะทริกเกอร์การขาดของ Knox ทำให้สูญเสียฟังก์ชันความปลอดภัยบางส่วนอย่างถาวร (เช่น Samsung Pay); จะล้างข้อมูลที่ได้รับการปกป้องทั้งหมด; ส่งผลกระทบต่อการรับประกัน</strong> โดยเฉพาะคือ:

- <strong>ฟิวส์นี้ใช้ได้ครั้งเดียว</strong>: ภายในโทรศัพท์มีฟิวส์ eFuse อยู่หนึ่งตัว เมื่อตรวจพบว่า BL ถูกปลดล็อก มันจะขาดอย่างถาวรทันที ไม่สามารถกู้คืนได้
- <strong>ฟังก์ชันที่ได้รับผลกระทบ</strong>: Samsung Pay (บัตรโดยสาร/บัตรธนาคาร), โฟลเดอร์ปลอดภัย Knox, การจัดการ MDM ขององค์กร, แอปประกันสุขภาพบางส่วน จะใช้งานไม่ได้ทั้งหมด
- <strong>บังคับล้างข้อมูล</strong>: หลังจากทริกเกอร์การขาดของฟิวส์ โทรศัพท์จะบังคับรีเซ็ตเป็นค่าโรงงาน ข้อมูลในเครื่องทั้งหมดจะถูกลบ (ข้อมูลบนคลาวด์ไม่ได้รับผลกระทบ)
- <strong>ผลกระทบต่อการรับประกัน</strong>:ทางการระบุชัดเจนว่า หลังจาก Knox ถูกทริกเกอร์แล้ว จะไม่ได้รับบริการรับประกันอีกต่อไป

#### 6. คำถามที่พบบ่อย (Q&amp; A)

::: div .qa-item .mt-3
{class="font-semibold mb-1"}
<i class="fas fa-question-circle text-primary mr-1"></i>Q1: หลังจากปลดล็อก Bootloader แล้วสามารถกลับไปล็อกใหม่ได้ไหม?

{class="mb-2 pl-6"}
<strong>A:</strong>สามารถล็อกใหม่ได้ โดยปกติจะต้อง Flash ชุดเฟิร์มแวร์อย่างเป็นทางการ และใช้สคริปต์ Flash เฉพาะ (เช่น ของ Xiaomi <code class="bg-gray-100 dark:bg-gray-800 px-1 rounded">flash_all_lock.bat</code>) เพื่อล็อกใหม่ได้ แต่โปรดทราบว่า หลังจากล็อกใหม่แล้ว การทริกเกอร์ความปลอดภัยบางอย่างที่เกิดจากการปลดล็อก (เช่น Knox ของ Samsung) อาจไม่สามารถย้อนกลับได้
:::

::: div .qa-item .mt-3
{class="font-semibold mb-1"}
<i class="fas fa-question-circle text-primary mr-1"></i>Q2: หลังจากปลดล็อกแล้วจะ Root ได้อย่างไร?

{class="mb-2 pl-6"}
<strong>A:</strong>การปลดล็อก Bootloader เป็นเพียงก้าวแรก การ Root มักจะต้องทำดังนี้:

{class="list-decimal pl-12 mb-2 space-y-1"}
1. Flash Recovery ที่กำหนดเอง (เช่น TWRP)
2. Flash Magisk หรือตัวจัดการ Root อื่นๆ ผ่าน Recovery เพื่อแก้ไข boot image จึงจะได้สิทธิ์ Root
:::
