### 第四十章：要件エンジニアリング——アイデアをAIが実行できる指示に変える

{class="chapter-intro mb-4"}
コンテキストエンジニアリングが「AIに背景をわからせる」ことだとすれば、要件エンジニアリングが解決するのは「AIに、今回は具体的に何をするのか知らせる」ことです。これはAIプログラミングの中で、人と人の差がいちばん表れるプロセスです——同じツール、同じモデルでも、驚くようなプロジェクトを作れる人もいれば、平凡なおもちゃしか作れない人もいます。その違いは多くの場合、技術力ではなく、要件を表現する力にあります。

#### 一、あいまいなアイデアから、構造化された要件へ

どのプロジェクトも、あいまいなアイデアから始まります——「家計簿アプリを作りたい」「個人サイトを作りたい」「ToDoリストのツールを作りたい」。アイデアそのものは問題ありませんが、それをそのままAIに投げると、成果物の質は完全に運まかせになります。要件エンジニアリングの目標は、このあいまいなアイデアを、AIが正確に実行できる構造化された要件に変えることです。

良いニュースがあります：構造化された要件のために、何十ページものPRDを書く必要はないのです。五つの質問に答えるだけで十分。私たちはこれを「要件五要素」と呼びます：

要件五要素とその例

この五つの要素を正式な文書にする必要はありません。頭の中でさっと一巡するだけでも十分です。大事なのは、「考えてから口を開く」習慣をつけることです。五つの質問にはっきり答えられるようになると、要件の説明が自然と構造化されていることに気づくはずです。

#### 二、要件を小さく分解する技法

大きめのプロジェクトでは、ひとつの要件の記述では足りません。大きな要件を、小さく、独立して確かめられるサブ要件に分解する必要があります。このプロセスを「要件分解」と呼びます。中核原則は：どのサブ要件も、独立に完成でき、独立に検証でき、独立に納品できる、ということです。

「個人用の家計簿アプリを作る」を例にすると、合理的な分解はこうなります：

1. 基本的な収支記録機能を作る（記録の追加・閲覧・削除ができる）。
2. カテゴリー機能を足す（各記録に食費、交通費などのタグを付ける）。
3. 月ごとの集計機能を作る（月単位で収支をまとめる）。
4. データの可視化を足す（グラフでお金の使い方を見せる）。

どのステップも、それ単体で動かして確かめられる機能のひとかたまりです。

:::inline div .quote-line
要件分解の黄金律：各ステップが終わるごとに、プロジェクトは「使えるもの」になっているべき——機能が粗末でも。永遠に「全部中途半端で、何ひとつ使えない」状態で止めてはいけません。
:::

この分解のしかたには、二つの良さがあります。第一に、進み具合が常に見えること——一歩終えるたびにアプリに機能がひとつ増え、このプラスのフィードバックは長期のプロジェクトにとって非常に大事です（人間は達成感が必要ですからね）。第二に、AIへのひとつひとつのタスクが十分小さくなり、「AIの理解のずれ」のリスクを下げます——タスクが小さいほどAIの理解は正確になり、成果物の質も上がります。

#### 三、PRD作成のテンプレートと実践

大きめのプロジェクト（フロントエンドとバックエンド、複数の機能モジュールを持つフルスタックアプリなど）では、要件五要素だけでは足りないことがあります。そのときは、より正式なプロジェクト要件文書（PRD）を書きます。誤解しやすいのはここです：PRDはAIのために書くものではありません——自分自身のために書くものです。自分の考えを整理できてこそ、AIにさらに正確な指示を出せるようになります。

良いPRDは長くなくて構いませんが、六つの部分を含めるべきです：プロジェクト概要（ひとことで何を作るかはっきり）、機能リスト（各機能点の中身）、技術方式（どんな技術スタックか、おおまかなアーキテクチャ）、データモデル（中核のデータ構造）、画面の記述（主要なページの見た目）、開発計画（何ステップで完成させるか）。

::: div .code-block
:::inline div .code-head
<span>PRD.md</span><span class="dots">···</span>
:::

```
# 個人家計簿アプリ PRD
## プロジェクト概要
軽量な個人家計簿アプリ。収支記録・カテゴリー・月次集計・データの可視化に対応。
## 機能一覧
1. 収支の記録：金額、種別（収入/支出）、カテゴリー、メモ、日付
2. カテゴリー管理：食費・交通・買い物・娯楽・その他をプリセット
3. 月次集計：月ごとの総収入・総支出・残高
4. 支出の可視化：円グラフでカテゴリー別の割合を表示
5. データ書き出し：CSVで出力
## 技術方案
- フロントエンド：React + TypeScript + Tailwind CSS
- データ保存：localStorage（バックエンド不要）
- グラフ：Chart.jsを使用
- ビルド：Vite
## データモデル
Record {
  id: string
  amount: number
  type: 'income' | 'expense'
  category: string
  note: string
  date: string  // YYYY-MM-DD
}
## 開発プラン
Step 1: 基本の記録機能 (CRUD)
Step 2: カテゴリー管理
Step 3: 月次集計
Step 4: データの可視化
Step 5: データ書き出し
```
:::

このPRDの書き方のスタイルに注目してください：長文ではなく、簡潔なリストと構造化されたフォーマットを使います。各機能点は明確に定義し、データモデルはシンプルな型で記述します。このスタイルのPRDは自分で読んでもわかりやすく、AIに渡したときも、AIが各要件を正確に理解できます。

#### 四、実践：アイデアから具体案までを完全に一巡してみる

机上の空論ではおもしろくないので、ひとつの完全な例で要件エンジニアリングの全プロセスをなぞってみましょう。あなたのアイデアはこうです：「毎日何を学んだかを記録できる、学習トラッカーが欲しい」。

第一ステップ：要件五要素を一巡します。

- Who：個人使用。
- What：毎日の学習内容を記録し、学習時間を追跡し、学習の進み具合をふりかえられるツール。
- Why：続けて学ぶ習慣を身につけ、自分の積み重ねを見たい。
- How：まずWeb版を作り、データはブラウザのローカルに保存する。
- Constraint：ゼロベースでの開発、1週間以内にコア機能を完成させる。

第二ステップ：要件を分解します。

1. Step 1：「学習項目の記録」機能を作る（日付、内容、時間）。
2. Step 2：「学習時間の集計」を追加する（今日、今週の累計）。
3. Step 3：「学習カレンダー」の表示を作る（GitHubのコントリビューショングラフのように見せる）。
4. Step 4：「学習のふりかえり」機能を追加する（過去のある日の記録をランダムに見せて、復習を助ける）。

第三ステップ：短いPRDを書きます。長くはいりません——上の分解そのものがPRDの本体になります。それを.mdファイルにまとめてプロジェクトのルートに置き、あなたとAIの共通の参照資料にしましょう。

第四ステップ：最初の開発を始めます。AIへの指示はこうなります：

::: div .code-block
:::inline div .code-head
<span>AIへの指示</span><span class="dots">···</span>
:::

```
学習トラッカーの最初の機能——学習記録の登録が必要です。
ユーザーは日付、学習内容、学習時間（分）を含む学習記録を1件追加できます。
データはlocalStorageに保存。
フロントエンドはReact + TypeScript。
完全な実装を示してください。
```
:::

この指示の特徴に注目してください：いまこのステップの目標（記録機能）だけを書き、ほかの機能を混ぜていない。技術の制約（React、TypeScript、localStorage）をはっきりさせている。AIに「何をするか」「どうやるか」がわかる十分な情報を与えながら、具体的な実装はAIに任せている。これが、要件エンジニアリングを経た、質の高いAIプログラミングの指示です。

::: div .chapter-summary
{class="font-semibold mb-1"}
本章のまとめ

- 要件五要素：Who / What / Why / How / Constraint——考えてから口を開く
- 要件分解の黄金律：どのステップが終わっても、プロジェクトは「使えるもの」になっている
- PRDは自分のために書くもの：概要、機能リスト、技術方式、データモデル、画面、計画
- 良い指示 ＝ いまのステップだけを書く＋制約をはっきりさせる＋「何をするか」を言い「どうやるか」は言わない
- 完全シミュレーションの型：五要素 → 分解 → PRD → 指示、の四ステップ
:::
