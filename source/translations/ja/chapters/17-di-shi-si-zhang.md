#### 一、なぜパスワードマネージャーが必要？

パスワードマネージャーがこのジレンマを解決：マスターパスワード一つだけ覚えれば、他のすべてのパスワードを覚えてくれます。

二、パスワードマネージャーの仕組み

#### 二、パスワードマネージャーの仕組み

1. <strong>：すべてのパスワードは高強度暗号化で保存され、あなただけが復号可能。</strong>マスターパスワード
2. <strong>：パスワード保管庫をロック解除するためのマスターパスワードを設定。マスターパスワード自体はサーバーに保存されません。</strong>自動入力
3. <strong>：ウェブサイトやAppのログイン画面で、パスワードマネージャーが自動的にIDとパスワードを入力。</strong>パスワード生成
4. <strong>：ランダムで複雑なパスワードを生成し、セキュリティを向上。</strong>三、主流パスワードマネージャーのおすすめ

#### 三、暗号化原理の概要

パスワードマネージャーの暗号化原理を理解すると、サービスプロバイダーが信頼に値するかを判断できます。以下、分かりやすい言葉でいくつかの核心概念を説明します。

##### 1. AES-256暗号化

AES（Advanced Encryption Standard）は米国国立標準技術研究所（NIST）が認可した共通鍵暗号アルゴリズムで、銀行、軍、政府で広く使用されています。「256」は鍵長が256ビットであることを意味し——理論上、宇宙の年齢を超える時間がないと総当たり攻撃で破れません。主流のパスワードマネージャー（1Password、Bitwarden、KeePassなど）はすべてAES-256でパスワード保管庫を暗号化しています。

##### 2. ゼロナレッジアーキテクチャ（Zero-Knowledge Architecture）

「ゼロナレッジ」とはサービスプロバイダーが何も保存しないということではなく、<strong>暗号化と復号はあなたのデバイスのローカルで完結し、サーバーは暗号化済みの暗号文のみを保存する</strong>。具体的な流れ：

1. クライアントでマスターパスワードを入力。
2. クライアントはマスターパスワードから暗号化鍵を派生させます（この処理はあなたのスマホ/PC上で行われます）。
3. 暗号化された暗号文のみがサーバーにアップロードされます。
4. 次回ログイン時、サーバーは暗号文を送信し、クライアントが再びマスターパスワードで復号します。

重要なポイント：<strong>マスターパスワード自体はあなたのデバイスから一切送信されません</strong>。サーバー上にもありません。そのため、仮にサービス提供元がハッキングされても、攻撃者が手にするのは解読不可能な暗号文の山に過ぎません——マスターパスワードを推測されない限り。

::: div .info-box .rounded-lg .p-4 .mt-3
{class="font-semibold"}
<i class="fas fa-lightbulb mr-2"></i>なぜ「ゼロナレッジ」はサービス提供者にもパスワードを見せないのか？

{class="mt-1"}
暗号化鍵はあなたのマスターパスワードから派生し、マスターパスワードはあなたの頭の中にのみ存在し、ローカルデバイス上でのみ使用されるからです。サービス提供者のサーバーにはマスターパスワードも暗号化鍵もなく、暗号文しかありません。だからこそ、Bitwarden、1Password などの正規サービス提供者は「私たちもあなたのパスワードを見ることはできません」と明確に宣言しているのです——見たくないのではなく、技術的に不可能なのです。
:::

##### 3. 鍵派生関数：PBKDF2 と Argon2

マスターパスワードは暗号化鍵としてそのまま使えません——「鍵派生関数」による処理が必要です。この関数の役割は<strong>あえて計算を遅くすること</strong>ことで、ハッカーの総当たり攻撃のコストを非現実的なレベルまで引き上げます。

- <strong>PBKDF2</strong>: 古い標準規格で、iCloud キーチェーン、Bitwarden、LastPass などに広く使われています。反復ハッシュ（通常10万回以上）で破解を遅延させます。
- <strong>Argon2</strong>: 2015年パスワードハッシュコンテスト優勝で、PBKDF2 よりモダンです。「計算コスト」に加え「メモリコスト」も導入し、GPU/ASIC などの専用ハードウェアでも加速破解が困難です。Bitwarden、KeePassXC などが既にサポートしています。

反復回数が多いほど安全ですが、ロック解除速度も遅くなります。正規サービス提供者は使用する派生アルゴリズムと反復回数を公開し、セキュリティコミュニティによる監査を可能にしています。

##### 4. 事例警鐘：LastPass 2022年データ漏洩

2022年8月、老舗パスワードマネージャー LastPass は開発環境への侵入を公表しました。同年11月にはさらに、ハッカーがユーザーのパスワード保管庫のバックアップ（暗号化された暗号文）を持ち出したことを明らかにしました。この事件の重要な教訓：

- <strong>ゼロナレッジアーキテクチャが最低限を守った</strong>: パスワード保管庫自体が暗号化されているため、ハッカーは暗号文を手にしても解読できません——ユーザーのマスターパスワードが十分に強いことが前提です。
- <strong>弱いマスターパスワードのユーザーが最も危険</strong>: ハッカーは弱いマスターパスワードをオフラインで総当たり攻撃できるため、弱いマスターパスワードや使い回しているユーザーは実質的なリスクに直面します。
- <strong>メタデータも漏洩</strong>: パスワードの内容は暗号化されていますが、サイトURLやメモなどのメタデータは暗号化されていない可能性があり、ユーザーがどのサービスを利用しているかが露出します。

::: div .warning-box .rounded-lg .p-4 .mt-3
{class="font-semibold"}
<i class="fas fa-exclamation-triangle mr-2"></i>LastPass 事件から学んだこと

{class="mt-1"}
第一に、マスターパスワードは長くユニークである必要があります（16文字以上、大文字・小文字・数字・記号を含む）。第二に、Argon2id をサポートし反復回数の多いサービス提供者を優先しましょう。第三に、高価値アカウント（銀行、メール）には必ず独立した二要素認証を設定し、パスワードマネージャーだけに頼らないようにしましょう。
:::

#### 五、パスワード強度の本当の評価

パスワードマネージャーは一般的に「パスワード強度」インジケーター（赤/黄/緑）を表示しますが、この評価は長さと文字の種類しか見ておらず、包括的ではありません。パスワードが本当に安全かを判断するには「エントロピー」と「漏洩の有無」を考慮する必要があります。

##### 1. エントロピー（Entropy）：パスワード強度の科学的尺度

「エントロピー」はパスワードの不確実性を測る指標で、単位はビットです。エントロピーが高いほど、総当たり攻撃に必要な試行回数が多くなります。

- <strong>"123456"</strong>: エントロピーが極めて低く、瞬時に破解されます。
- <strong>"P@ssw0rd"</strong>: 一見複雑に見えますが、すべての辞書攻撃リストに載っており、エントロピーは依然として低いです。
- <strong>"correct horse battery staple"</strong>: 4つのランダムな単語、エントロピー約44ビットで、破解難度は「P@ssw0rd」をはるかに超えます。
- <strong>16文字のランダム文字（大文字・小文字+数字+記号を含む）</strong>: エントロピー約100ビット、現在の計算力では総当たり攻撃不可能です。

結論：<strong>「長さ + ランダム性」は「複雑な記号」よりも重要</strong>。これがパスワードマネージャーが生成するランダムな長いパスワードが本当に安全である理由です。

##### 2. HaveIBeenPwned：あなたのパスワードが漏洩していないか確認

セキュリティ研究者 Troy Hunt が運営する <a href="https://haveibeenpwned.com" class="text-primary hover:underline" target="_blank" rel="noopener">haveibeenpwned.com</a> は過去の大規模データ漏洩で流出したアカウントとパスワードを収録しています。以下のことができます：

1. メールアドレスを入力して、あなたのアカウントがいずれかの漏洩事件に関与していないか確認。
2. Pwned Passwords 機能を使って、特定のパスワードが既知の漏洩データベースに含まれているか確認（パスワードマネージャーやブラウザにこの機能が組み込まれています）。

もしパスワードが漏洩データベースに含まれていたら、<strong>どんなに複雑に見えてもすぐに変更する必要があります</strong>——辞書攻撃はこれらの既知パスワードを優先的に試すからです。

::: div .info-box .rounded-lg .p-4 .mt-3
{class="font-semibold"}
<i class="fas fa-shield-alt mr-2"></i>k-匿名性クエリの原理

{class="mt-1"}
HaveIBeenPwned にパスワードを入力するとまた漏洩するのでは？心配いりません。現代のクエリは「k-匿名」プロトコルを採用しています：ブラウザはパスワードハッシュの最初の5文字だけをサーバーに送信し、サーバーはその5文字で始まる全ハッシュリストを返し、ローカルで照合します。つまり、サーバーはあなたの完全なパスワードハッシュを見ることはありません。1Password、Bitwarden の「漏洩パスワード検出」もこの仕組みで動作しています。
:::

#### 六、Passkey：パスワード不要ログインの未来

2024-2026年、パスワード技術は革命を遂げようとしています——<strong>Passkey（パスキー）</strong>が従来のパスワードを完全に淘汰する可能性があります。Apple、Google、Microsoft の3大プラットフォームが共同推進し、FIDO Alliance と W3C が支持する、数十年で最大のログイン方式の変革です。

##### 1. Passkey とは？

Passkey は FIDO2 / WebAuthn 標準に基づき、<strong>デバイス上の鍵ペア</strong>でパスワードを置き換えます。原理を簡略化すると：

- あなたのスマホが鍵のペアを生成します：<strong>公開鍵</strong>（ウェブサイトに登録）+ <strong>秘密鍵</strong>（デバイスのセキュリティチップに永久保存）。
- ログイン時、ウェブサイトが「チャレンジ」を送信し、あなたのスマホが秘密鍵で署名し、ウェブサイトが公開鍵で検証します。
- 署名前に生体認証（Face ID / 指紋）またはデバイスの PIN で本人確認が必要です。
- このプロセス全体で、<strong>パスワードは一切ネットワーク上で送信されません</strong>。

##### 3. 各プラットフォームのサポート状況

- <strong>Apple iCloud キーチェーン Passkey</strong>: iOS 16+ / macOS Ventura+ でネイティブサポート。Passkey は同じ Apple ID でログインしている全デバイス間で同期でき、新デバイスでサイトにログインする際に再作成不要です。
- <strong>Google パスワードマネージャー Passkey</strong>: Android + Chrome でネイティブサポート。Passkey は Google アカウントに保存され、Android デバイス間で同期。2023年以降、Google 個人アカウントで Passkey ログインをサポート。
- <strong>Microsoft</strong>: Windows 11 / Edge が Passkey をサポート。Microsoft アカウント、Outlook、Office などで順次 Passkey ログインを提供し、Microsoft Authenticator で管理可能。
- <strong>1Password / Bitwarden</strong>: Passkey の作成、保存、クロスプラットフォーム同期をサポートし、単一エコシステムに縛られません。

::: div .info-box .rounded-lg .p-4 .mt-3
{class="font-semibold"}
<i class="fas fa-lightbulb mr-2"></i>クロスデバイス同期が重要なブレークスルー

{class="mt-1"}
初期の Passkey の最大の課題は「単一デバイスにバインド」——スマホを替えるたびに再作成が必要でした。2023年以降、Apple、Google、Microsoft は Passkey のクラウド同期を実現：iCloud キーチェーンは Apple デバイス間で同期、Google パスワードマネージャーは Android デバイス間で同期。1Password などのサードパーティはクロスエコシステム同期を実現しました。これは Passkey がパスワードを代替する実用性を備えたことを意味します。
:::

##### 4. スマホで Passkey を作成・使用する方法

<strong>iOS（iPhone）の操作手順：</strong>

1. Passkey をサポートするウェブサイト（Google、Microsoft、Amazon、eBay、PayPal など）のアカウントセキュリティページで「パスキーを追加 / Add passkey」を選択。
2. システムが Face ID / Touch ID の認証画面を表示し、認証成功後 Passkey が自動生成され iCloud キーチェーンに保存されます。
3. 次回そのサイトにログインする際、ユーザー名入力後に「iPhone でログイン」を選択し、Face ID を一度認証するだけです。
4. 管理画面：設定 → パスワード → 該当サイトを見つけると Passkey エントリーが表示されます。

<strong>Android の操作手順：</strong>

1. Passkey をサポートするウェブサイトのアカウントセキュリティページで「パスキーを追加」を選択。
2. Google パスワードマネージャーのポップアップ → Google アカウントを選択 → 画面ロック認証（指紋/パターン/PIN）。
3. Passkey は Google パスワードマネージャーに自動保存され、同じアカウントの Android デバイス間で同期されます。
4. 次回ログイン時に「Passkey を使用」を選択し、画面ロックを解除するだけです。
5. 管理画面：Android 設定 → パスワード、パスキー、自動入力 → パスワードマネージャー → google.com。

##### 5. Passkey のクロスデバイスログイン

Windows PC で、iPhone にしか Passkey がないサイトにログインする場合、QRコードで認証できます：

1. サイトのログインページで「Passkey を使用」を選択。
2. 「他のデバイスを使用」を選択。
3. PC にQRコードが表示されるので、iPhone でスキャン。
4. iPhone に Face ID 認証が表示され、確認後 PC 上でサイトのログインが完了します。

このプロセスは Bluetooth + インターネットの二重暗号化通信で行われ、Passkey の秘密鍵が iPhone を離れることはありません。

<i class="fas fa-exclamation-triangle mr-2"></i>移行期のアドバイス

{class="mt-1"}
Passkey はパスワードを完全に置き換えたわけではありません——多くのサイトはまだ「Passkey + パスワード」の併用段階です。高価値アカウントで Passkey を優先的に有効化しますが、<strong>従来のパスワードをすぐに削除しないでください</strong>、バックアップとして残しましょう。同時にパスワードマネージャーの使用も続けてください。すべてのサイトが Passkey に対応しているわけではないからです。Passkey は「パスワードマネージャーの強力な補完」として捉え、「即時置き換え」とは考えないでください。
:::

#### 七、ハードウェアセキュリティキー

一般ユーザーより高いセキュリティを求める場合——例えば大量の暗号資産を保有している、経営者/ジャーナリスト/活動家である、企業のコアアカウントを保護するなど——ハードウェアセキュリティキーはSMS認証コードより信頼性の高い選択肢です。

##### 1. ハードウェアセキュリティキーとは？

ハードウェアキーは物理デバイス（USBメモリのような形状）で、内部のセキュリティチップにあなたの秘密鍵を保存し、物理的接触または NFC で認証を完了します。代表的な製品：

- <strong>YubiKey</strong>（Yubico社）：最も主流。FIDO2/WebAuthn、U2F、OTP、PIV、OpenPGP をサポートし、USB-C / USB-A / NFC など多様なインターフェースに対応。5シリーズで50-70ドル。
- <strong>Google Titan</strong>: Google 製。USB-C + NFC / Bluetooth、約30-40ドル。
- <strong>OnlyKey</strong>: オープンソースの代替品、複数プロトコルをサポート。
- <strong>中国産代替品</strong>: 飛天誠信 ePasskey など、より手頃な価格。

##### 2. なぜハードウェアキーはSMS認証コードより安全なのか？

- <strong>フィッシング耐性</strong>: Passkey と同様、ハードウェアキーは本物のドメインにのみ応答し、フィッシングサイトは認証コードを騙し取れません。
- <strong>SIM ハイジャック耐性</strong>: SMS認証コードはSIMスワップ攻撃で傍受される可能性がありますが、ハードウェアキーは電話番号を必要としません。
- <strong>中間者攻撃耐性</strong>: FIDO2 プロトコルは毎回の署名にチャレンジ値を含み、リプレイできません。
- <strong>物理的分離</strong>: 秘密鍵は常にハードウェアチップ内にあり、マルウェアがPCを侵害しても読み取れません。

##### 3. 適用シーン

- 暗号資産取引所アカウント、ウォレット復元。
- 企業SSO、リモートワークVPN、SSHサーバーログイン。
- メール、GitHub、ソーシャルメディアなどの「メインアカウント」——一度侵害されると他の全アカウントがリセットされます。
- ジャーナリスト、弁護士、経営者など高感度人物。

##### 4. ハードウェアキーを二要素認証に設定する方法

Google アカウント + YubiKey を例に：

1. YubiKey を購入（2本まとめて購入を推奨、1本は日常用、1本はバックアップ、別々の場所に保管）。
2. myaccount.google.com にログイン → セキュリティ → 2段階認証。
3. 「セキュリティキーを追加」を選択 → YubiKey を USB-C ポートに挿入、またはスマホのNFCセンサーにかざす。
4. 指示に従って YubiKey の金属接点に触れて登録を完了。
5. 2本目のバックアップキーの登録を推奨。
6. 「2段階認証」の設定で、ハードウェアキーを優先認証方式にし、SMS認証コードをバックアップにします。

主流サポートサイト：Google、GitHub、Microsoft、Apple ID、Facebook、Twitter、Dropbox、GitLab、AWS、Coinbase、Binance など。

::: div .info-box .rounded-lg .p-4 .mt-3
{class="font-semibold"}
<i class="fas fa-lightbulb mr-2"></i>デュアルキー戦略

{class="mt-1"}
ハードウェアキーの最大のリスクは「紛失」です。推奨：① 異なる2本のキーを同時に登録；② 1本は随身携帯（キーホルダー）、1本は自宅の金庫または銀行貸金庫に保管；③ 一部サイトでは「バックアップ復旧コード」を印刷してオフライン保存可能。これで主キーを紛失してもアカウントから永久に締め出されることはありません。
:::

::: div .warning-box .rounded-lg .p-4 .mt-3
{class="font-semibold"}
<i class="fas fa-exclamation-triangle mr-2"></i>購入ルートに注意

{class="mt-1"}
必ず公式ストアまたは正規代理店から購入し、中古や出所不明のキーは買わないでください——理論上、プリセットされたハードウェアにバックドアが仕込まれている可能性があります。YubiKey のファームウェアは出荷後に更新できませんが、Yubico は継続的にセキュリティ公告を発信するので公式サイトを確認してください。
:::

#### 八、家族/チームのパスワード共有

家庭では Netflix、家庭用 Wi-Fi、ルーター管理画面、スマートロックのパスワードを家族で共有。チームではサーバー、データベース、ソーシャルメディアアカウントを複数人で共同利用します。<strong>WeChat でパスワードを送信したり、共有ドキュメントに書いたりするのは高危険</strong>——チャット履歴やドキュメント権限が漏洩すれば、パスワードも漏洩します。

##### 1. 1Password の「共有保管庫」（Vault）

1Password は家族・チーム共有の代表的な製品です。その核心仕組みは<strong>複数の保管庫</strong>：

- <strong>個人保管庫</strong>: あなただけが閲覧可能。銀行、メールなどのプライベートアカウント。
- <strong>共有保管庫</strong>: 家族やチームメンバー全員が閲覧可能。Netflix、家庭用 Wi-Fi、共有クレジットカードなど。
- <strong>権限レベル分け</strong>: チーム版では一部メンバーを「閲覧のみ」や「閲覧のみ・編集不可」に設定できます。

家族やチームメンバーはマスターパスワードを共有する必要がなく、各自のアカウントでログインしますが、権限を付与された共有保管庫の内容を閲覧できます。パスワード変更後、全メンバーにリアルタイムで同期されます。

##### 2. Bitwarden の「組織」機能

Bitwarden の無料版は個人パスワード共有をサポート（「Send」機能で期限付きで1件のパスワードを共有）。有料版では「組織」を作成し、複数エントリーを家族やチームメンバーと共有でき、権限を細かく設定可能。Bitwarden はセルフホストオプションも提供し、データ主権を重視する企業に適しています。

##### 3. 家庭シーン：Netflix、Wi-Fi などのパスワードを安全に共有する方法

- <strong>Netflix / 動画サイト</strong>: 1Password Families の「共有保管庫」にログインパスワードを保存し、家族メンバーが各自でログイン。グループチャットに送信する必要なし。
- <strong>家庭用 Wi-Fi パスワード</strong>: iOS デバイス間では AirDrop で来客に Wi-Fi パスワードを直接共有でき、口頭で伝える必要なし。Android 12+ にも「近距離共有でWi-Fi共有」機能があります。
- <strong>スマートロック、スマート家電</strong>: なるべくメーカーAppの「家族メンバー」機能で各自に個別アカウントを作成し、1つの管理者アカウントを共有しないようにしましょう。
- <strong>家庭用ルーター管理画面</strong>: 管理者パスワードは 1Password 共有保管庫に保存し、ゲスト用 Wi-Fi は別の SSID で設定。

<i class="fas fa-lightbulb mr-2"></i>1Password Families のコストパフォーマンス

1Password Families は約4.99ドル/月で最大5人の家族メンバーをサポート。各人に独立した個人保管庫 + 4つの共有保管庫。一人当たり1ドル/月未満で、現在家庭共有で最も優れた体験を提供します。Bitwarden の家庭版は10ドル/年で6人サポートし、コストパフォーマンスはより高いですが、インターフェース体験はやや劣ります。

##### 4. チームシーン：サーバー/データベースパスワード共有

- <strong>1Password Teams / Business</strong>: 部門やプロジェクトグループごとに複数の保管庫を作成し、きめ細かい権限管理が可能。すべてのアクセス行為を監査できます。
- <strong>Bitwarden Teams / Enterprise</strong>: オープンソース方案、セルフホスト可能。エンタープライズ版はSSO連携、ディレクトリ同期をサポート。
- <strong>職務分離の原則</strong>: 管理者パスワードを一人だけが掌握すべきではありません——2-3名の「緊急連絡先」を設定し、キーパーソンの離職/休暇時も業務が継続するように。
- <strong>離職プロセス</strong>: 従業員の離職時にパスワードマネージャーのアクセス権を即時取り消し、必要に応じてその従業員が接触した高感度パスワードをすべてローテーション。

##### 5. 緊急アクセス（Emergency Access）：万が一の時のために

こんなシーンを想像してください：あなたが家庭のすべての重要アカウントを単独で管理しているが、意図せず入院したり亡くなったりした場合、家族が銀行、メール、保険のアカウントにログインできない。<strong>「緊急アクセス」機能</strong>はまさにこのために設計されました——信頼する家族/友人を認可し、あなたが応答できない時にパスワード保管庫にアクセスできるようにします。

<strong>Bitwarden 緊急アクセスの設定：</strong>

1. Bitwarden Web Vault にログイン → 設定 → 緊急アクセス。
2. 信頼する連絡先のメールアドレスを追加し、相手を招待。
3. 「待機期間」を設定（7-14日を推奨）：相手がリクエストしてからあなたが確認するまでの時間枠。
4. 待機期間内にあなたが応答しない（拒否もしない）場合、期間満了後に相手が自動的にアクセス権を取得します。
5. いつでも手動でリクエストを拒否したり緊急アクセス権を取り消すことができます。

<strong>1Password 緊急アクセス：</strong>

1. 1Password は直接「緊急アクセス」とは呼びませんが、「家族/チーム組織」機能で実現できます——家族を家族版に追加した後、一部エントリーを「共有保管庫」に配置。
2. 個人版ユーザーには、マスターパスワードを高度に信頼する家族に伝えるか、密封した封筒で金庫に保管することを推奨。
3. 1Password は「復旧コード」も提供しており、二要素認証を有効にする際は必ず印刷して保管してください。
