### Κεφάλαιο 44: Πρακτική από το 0 στο 1 — η πλήρης πορεία ενός ολόκληρου έργου

{class="chapter-intro mb-4"}
Η θεωρία τελείωσε — ήρθε η ώρα για δράση. Αυτό το κεφάλαιο δεν είναι ένα απλό μάθημα «πληκτρολόγησε μαζί μου», αλλά μια πρακτική μεθοδολογία του «πώς σκέφτεσαι, πώς ρωτάς, πώς επαληθεύεις». Με τρία έργα διαφορετικής δυσκολίας θα δούμε την πλήρη διανοητική πορεία από τις απαιτήσεις έως το τελικό προϊόν. Ό, τι εργαλείο κι αν χρησιμοποιείς, αυτή η ροή ισχύει.

#### 1. Έργο 1: Μίνι site προσωπικών εργαλείων (για αρχή)

##### 1. Σκέψη απαιτήσεων

Στόχος: δημιουργία μιας σελίδας προσωπικών εργαλείων που δείχνει τις εισόδους 3-4 πρακτικών μικρο-εργαλείων. Είναι καθαρά frontend έργο, χωρίς backend και βάση δεδομένων. Το ζητούμενο δεν είναι πόσο σύνθετα είναι τα ίδια τα εργαλεία, αλλά να ζήσεις την πλήρη πορεία «από τις απαιτήσεις στο τελικό προϊόν».

Με τα πέντε στοιχεία των απαιτήσεων: Who — για προσωπική χρήση. What — μια σελίδα που δείχνει τις εισόδους των εργαλείων. Why — να μαζεύονται τα συχνά χρησιμοποιούμενα εργαλεία σε μία σελίδα για εύκολη πρόσβαση. How — ένα αρχείο HTML+CSS+JS, χωρίς frameworks. Constraint — να ολοκληρωθεί σε 30 λεπτά, χωρίς ανάπτυξη (deployment).

##### 2. Δίνεις την εντολή

Με βάση την αρχή «Think Before Coding», η εντολή σου πρέπει να περιέχει αρκετή πληροφορία ώστε η AI να καταλάβει τον στόχο, χωρίς όμως να ορίζεις κάθε λεπτομέρεια υλοποίησης:

Φτιάξε μια σελίδα προσωπικών εργαλείων με απαιτήσεις:

2. Σκούρο θέμα, μοντέρνο μινιμαλιστικό στυλ
3. 4 κάρτες εργαλείων:
   - εργαλείο σύνοψης κειμένου
   - μετρητής λέξεων

   - γεννήτρια QR
4. Κάθε κάρτα με εικονίδιο, τίτλο και σύντομη περιγραφή
5. Οι κάρτες με animation στο hover
6. Responsive, usable σε κινητό
7. Μπάρα τίτλου στην κορυφή
Δώσε απευθείας το πλήρες αρχείο HTML.

##### 3. Παραλαβή και επανάληψη

Όταν η AI δώσει τον κώδικα, κάνε την παραλαβή με τον τριεπίπεδο έλεγχο της επαλήθευσης επανάληψης. Πρώτο επίπεδο — επαλήθευση λειτουργίας: ανοίγει το αρχείο στον browser; Εμφανίζονται και οι 4 κάρτες; Δουλεύει σωστά το animation στο hover; Δεύτερο επίπεδο — επαλήθευση ορίων: η διάταξη είναι σωστή σε μέγεθος οθόνης κινητού; Τυλίγονται οι κάρτες σε νέες γραμμές όταν το παράθυρο είναι πολύ στενό; Τρίτο επίπεδο — επαλήθευση αρχιτεκτονικής: είναι ευανάγνωστος ο κώδικας; Το CSS είναι ενσωματωμένο σε ένα tag style; Υπάρχουν εμφανή περιττά κομμάτια;

Αν θες να υλοποιήσεις και τη λειτουργία κάποιας κάρτας εργαλείου (κι όχι μόνο την είσοδο), μπορείς να την προσθέτεις σταδιακά — κάθε φορά πρόσθετε τη λειτουργία ενός εργαλείου, επαλήθευσε και μετά πρόσθεσε την επόμενη. Αυτή είναι η πρακτική εφαρμογή της στρατηγικής των «μικρών γρήγορων βημάτων».

#### 2. Έργο 2: Full-stack σύστημα λογιστικής (ενδιάμεσο)

##### 1. Σκέψη απαιτήσεων και PRD

Στόχος: μια full-stack εφαρμογή λογιστικής με frontend, backend και βάση δεδομένων. Αυτό το έργο είναι πολύ πιο σύνθετο από το πρώτο και χρειάζεται τις μεθόδους μηχανικής απαιτήσεων του Κεφαλαίου 40.

Γράψε πρώτα PRD. Με το πρότυπο της ενότητας 3 του Κεφαλαίου 40, γράψε επισκόπηση έργου, λίστα λειτουργιών, τεχνική λύση, μοντέλο δεδομένων και σχέδιο ανάπτυξης. Στην επιλογή της τεχνικής λύσης, λάβε υπόψη την αρχή «Simplicity First» — frontend με React αλλά χωρίς σύνθετη διαχείριση state όπως Redux· backend με Node.js αλλά χωρίς microservices· βάση δεδομένων SQLite αντί για PostgreSQL (στο στάδιο ανάπτυξης).

Το σχέδιο ανάπτυξης σπάει σε 5 βήματα: Step 1 ο σκελετός του backend API (server Express + SQLite + CRUD interfaces)· Step 2 οι βασικές σελίδες frontend (λίστα εγγραφών + φόρμα προσθήκης)· Step 3 σύνδεση frontend-backend (κλήσεις API + εμφάνιση δεδομένων)· Step 4 λειτουργίες κατηγοριών και φίλτρων· Step 5 μηνιαία σύνοψη και απλά γραφήματα. Κάθε βήμα, όταν ολοκληρώνεται, αφήνει κάτι «που δουλεύει».

##### 2. Ρυθμίζεις το αρχείο μνήμης του έργου

Πριν ξεκινήσεις τον κώδικα, φτιάξε πρώτα το αρχείο μνήμης του έργου. Είναι η βασική πρακτική της μηχανικής συμφραζομένων — να γνωρίζει η AI το υπόβαθρο του έργου στην αρχή κάθε συνομιλίας.

::: div .code-block
:::inline div .code-head
<span>CLAUDE.md</span><span class="dots">···</span>
:::

```
# Έργο: full-stack εφαρμογή λογιστηρίου
## Επισκόπηση
Εφαρμογή προσωπικού λογιστηρίου, με καταγραφή, κατηγορίες και μηνιαία σύνοψη.
## Τεχνολογίες
- Frontend: React + TypeScript + Vite
- Backend: Node.js + Express + TypeScript
- Βάση δεδομένων: SQLite (με better-sqlite3)
- Κοινοί ορισμοί τύπων frontend-backend
## Συμφωνίες API
- Βασική διαδρομή: /api
- Μορφή απάντησης: { success: boolean, data: any, error: string }
- Στυλ RESTful
## Μοντέλο δεδομένων
Record { id, amount, type, category, note, date }
## Κανόνες κώδικα
- TypeScript σε αυστηρή λειτουργία
- Εσοχή 2 κενών
- Συναρτήσεις με σχόλιο JSDoc
- Σχόλια και μηνύματα commit στα κινεζικά
```

##### 3. Υλοποιείς βήμα-βήμα

Σύμφωνα με το σχέδιο ανάπτυξης, κάθε βήμα ολοκληρώνεται σε μια ξεχωριστή συνομιλία. Παρακάτω ένα παράδειγμα εντολής για το πρώτο βήμα:

::: div .code-block
:::inline div .code-head
<span>Οδηγίες στο AI (Step 1)</span><span class="dots">···</span>
:::

```
Χρειάζομαι τον σκελετό του backend API.
Απαιτήσεις:
1. Server Express, port 3001
2. Βάση SQLite, πίνακας records
3. Πεδία πίνακα records:
   id (TEXT PRIMARY KEY)
   amount (REAL)
   type (TEXT: 'income'|'expense')
   category (TEXT)
   note (TEXT)
   date (TEXT: YYYY-MM-DD)
4. API CRUD:
   GET /api/records - ανάκτηση όλων
   POST /api/records - προσθήκη
   PUT /api/records/:id - ενημέρωση
   DELETE /api/records/:id - διαγραφή
5. Middleware διαχείρισης σφαλμάτων
Δώσε πλήρη δομή κώδικα backend.
```
:::

Πρόσεξε τα χαρακτηριστικά αυτής της εντολής: περιγράφει μόνο το τρέχον βήμα (τον σκελετό του backend), χωρίς ανάμειξη απαιτήσεων frontend· απαριθμεί ρητά τα πεδία και τα interfaces (δίνει στην AI επαρκείς περιορισμούς), ενώ η συγκεκριμένη υλοποίηση την αποφασίζει η AI· ακολουθεί την αρχή «Goal-Driven Execution» — λέει «τι θα γίνει» και όχι «πώς θα γίνει».

Μόλις η AI δώσει τον κώδικα, επαλήθευσε αμέσως: τρέξε τον server και δοκίμασε με curl ή Postman αν κάθε interface δουλεύει σωστά. Όταν επιβεβαιώσεις ότι όλα είναι εντάξει, άνοιξε νέα συνομιλία για το Step 2 (βασικές σελίδες frontend). Κάθε βήμα ακολουθεί τον κύκλο «εντολή-επαλήθευση-νέα συνομιλία».

#### 3. Έργο 3: Εφαρμογή με ενίσχυση AI (προχωρημένο)

##### 1. Σύλληψη του έργου

Στόχος: μια εφαρμογή που συνδέεται με το API μεγάλου μοντέλου — π.χ. ένας «βοηθός μελέτης με AI»: ο χρήστης εισάγει το περιεχόμενο που μελετά και η AI φτιάχνει περίληψη, συνδέει σχετικές γνώσεις και προτείνει πηγές μάθησης. Το ιδιαίτερο του έργου: η ίδια η εφαρμογή σου καλεί AI, οπότε πρέπει να διαχειριστείς νέα ζητήματα όπως κλήσεις API, prompt engineering και διαχείριση σφαλμάτων.

Το πιο σημαντικό μάθημα αυτού του έργου: όταν «χρησιμοποιείς AI για να γράψεις κώδικα που καλεί AI», πρέπει να προσέχεις ιδιαίτερα το prompt engineering. Τα prompt που χρησιμοποιεί η εφαρμογή σου όταν καλεί το API του μεγάλου μοντέλου πρέπει κι αυτά να ακολουθούν τις αρχές που συζητήσαμε σε αυτόν τον οδηγό — σαφήνεια, συντομία, στόχευση.

##### 2. Κρίσιμα τεχνικά σημεία

Αυτό το έργο περιλαμβάνει μερικά τεχνικά σημεία που δεν συνάντησες στα δύο προηγούμενα έργα:

- Διαχείριση API κλειδιών: το κλειδί δεν μπαίνει ποτέ απευθείας στον κώδικα — δούλεψέ το με μεταβλητές περιβάλλοντος.
- Διαχείριση ροής απαντήσεων: οι απαντήσεις των μεγάλων μοντέλων συνήθως έρχονται σε ροή και πρέπει να εμφανίζονται σταδιακά.
- Έλεγχος κατανάλωσης Token: τα μεγάλα μοντέλα χρεώνονται ανά token, οπότε χρειάζεται έλεγχος της χρήσης σε επίπεδο εφαρμογής.
- Διαχείριση προτύπων Prompt: διαφορετικές λειτουργίες με διαφορετικά πρότυπα prompt, που χρειάζονται δομημένη διαχείριση.

Για όλα αυτά τα τεχνικά σημεία μπορείς να ζητήσεις τη βοήθεια της AI, αλλά πρέπει να καταλαβαίνεις το «γιατί» του καθενός — γιατί το κλειδί δεν μπαίνει στον κώδικα; γιατί χρειάζεται ροή απαντήσεων; γιατί ελέγχεται η κατανάλωση token; Μόνο όταν καταλάβεις το «γιατί» μπορείς να κρίνεις αν η λύση της AI είναι λογική.
