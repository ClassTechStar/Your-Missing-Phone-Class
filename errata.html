勘误页

《你缺失的那门手机课》· 这本书的错误怎么提、谁来改、多久改

先说清楚这一页在证明什么。
它证明的不是"这本书零错误"——一本 370 万字、每年手机界面都要换一次的书，不可能零错误。 它证明的是内容有人负责：错误报给谁、谁来改、多久改完、改在哪里，都写在这里。
时效公示：累计已处理 4 条勘误 · 最近修订 2026-11-20
「响应时间」从口号变成指标：数字随每次勘误修订更新，「几天前」按你打开本页的时间实时计算。

四种错误，四种处理方式

类型典型样子你该怎么办我们怎么处理
界面路径过时 你照着书点，找不到那个菜单了；或者名字改了、位置挪了 报勘误时附上你的机型和系统版本 改 path_db.json 里的路径条目，正文跟着改；大版本后整批巡检
事实有误 某个说法不对、某个数字错了、某个结论站不住 指出书里的原句和你认为错在哪 核实后改，并看是否需要连带改掉引用了这一条的别处
表述不清 读了三遍还是不知道该点哪里 指出哪一节、卡在哪一步 改写那一段；这类反馈往往比"错"更有价值
其它 错别字、链接失效、格式乱、翻译不同步 直接报 顺手修掉

报错模板：复制这段填就行

【章节】第十九章 手机故障排查与自救
【位置】第四节「手机变卡、发热」的第 2 段
【原文】打开【设置】→【电池】→【耗电排行】
【我的机型与系统】小米 14，HyperOS 2（Android 15）
【我这里的样子】我这里【设置】里没有「电池」这一项，只有「电量与性能」
【我做了什么】按书里的路径找了两遍
【我的判断】可能是系统版本不同导致菜单改了名？
【截图】（如有）

填不满也没关系。章节 + 你看到的实际样子这两项最重要，其余可以后补。

认领翻译：把某一章改到能读

14 种语言目前是机器翻译 + 术语统一，质量不承诺。我们不想假装它们和中文版一样好， 也不想让它们一直停在这里。如果你愿意认领一章：

  1. 在 语言分级页 选一个语言，记下它的星级；
  2. 在 「翻译认领」Issue 里写下语言 + 章节；
  3. 按 Issue 里的路径改 source/translations/<lang>/chapters/，跑 python -m bookkit i18n --check-spacing --fail-on error 与 python -m bookkit build --lang <lang> --verify；
  4. 提 PR，CI 会自动跑结构对齐与标点门禁。

从机翻到可读，不需要一次改完一本书，一章就够。改完的那一章会从两星升到三星的候选池。

已经确认并修好的问题

下面每一条都是真的在书稿里查出来、并且已经改掉的。写在这里是为了让你知道我们改了什么， 也为了让你知道反馈确实会变成改动。

已修 附录 C 按旧标题引用其他章，改名后变成死链 2026-11

现象
正文里出现「第 X 章《某某》」这种按标题写的交叉引用。章标题一旦改动，这些引用就指向了不存在的标题。
范围
全书 49 处，集中在附录 C（术语对照表）、附录 E、附录 G、附录 H
处理
改标题时同步改引用。现在术语表里的每一处《…》都能在正文里找到同名标题。

已修 侧栏标题与页面大标题对不上 2026-11

现象
侧边栏里显示的是简写标题（如「守护你的数字生活」），点进去页面大标题却是全称（如「守护你的数字生活——安全与隐私」）。不是错，但对不上号。
范围
28 个章节区块
处理
本次把一批章标题改成口语化短标题时，侧栏与正文同步更新；目录里查得到的名字与正文完全一致。

已修 列表项收尾符号全书不统一 2026-11

现象
同一个列表里，有的条目以句号结尾，有的以分号结尾，有的什么都不加。全书有一千多处条目以分号收尾。
范围
全书 2619 处
处理
统一成句号收尾。分号收尾的列表读起来像被机器切过。

已修 章节之间的路径没有统一基准 2026-11

现象
各章对"当前系统版本"的假设不一致，读者没法判断某条路径到底多久算新。
范围
全书 80 个含操作路径的章节
处理
每章开头加了版本锚点（本章路径按 iOS 18.x / HarmonyOS 5.x / Android 15 核对，2026 年 11 月）， 路径登记进 path_db.json，现在可以逐条查、逐条巡检。

我们的承诺

响应时间：勘误提交后中位 7 天内给出回应（"回应"包括确认收到并给出结论，不一定当场改完）。
修订节奏：每季度一个修订版，累计的勘误一起进。
改在哪里：路径错误改路径库，正文错误改正文——不是把正文改成一个新说法了事。

这个承诺的意义，比"120/120 章逐字核对通过"更大一些。 逐字核对证明的是排版忠于源稿；勘误响应证明的是内容有人负责。 前者是机器能管的事，后者是机器管不了、只能靠人管的事。
