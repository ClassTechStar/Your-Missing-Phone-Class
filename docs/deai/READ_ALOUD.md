## 一、怎么测的

三项信号各有可复跑的判据：

| 编号 | 类别 | 判据 |
| --- | --- | --- |
| **R1** | 喘不上气 | 一口气读不完的无标点连续段，或一句里塞了太多分句 |
| **R2** | 拗口 | 流程箭头串、连续顿号、同词重复、括号嵌套、中英数混排 |
| **R3** | 听了走神 | 段内连续几句长度几乎相同、连续同开头、一句里抽象词堆叠 |

## 四、一处被否决的机械修复（记录下来，免得以后重踩）

朗读体检最初打算配一个脚本，把「A → B → C → D → E」这种流程箭头串机械地改成编号列表（箭头是通用符号，编号列表是通用排版，理论上对所有语言成立）。

**实测否决**：本书的箭头链大多是**嵌在句中的操作路径**（`【设置】→【更多设置】→【内存】`），后面还跟着正文。加上四道护栏后只剩 4 处候选，逐条看下来**全部不安全**：

- 把 `旧机进：微信 → 我 → 设置 → …` 拆开，会在编号列表项里再嵌一个编号列表，Markdown 列表结构直接坏掉；
- 把 `…→【关于手机】或【运存与存储】里，名字也可能叫…` 拆开，后半句正文会被甩到列表外面；
- `路线：第十一章 → 第三十一章 → …` 是**章节导航表**，拆成列表反而更难一眼扫完。

结论：**这一类只能靠人判断**。方案 §6.3 说的「人的语感是终点裁判」，在流程箭头这件事上表现得最具体。相关工具已删除，不留在仓库里当陷阱。

## 五、这一轮改了什么、还剩什么

### 已改

- **v1.9 中文（120 章）**：R1/R2/R3 逐条改，重点是把「段内三句等长」的机器节奏打散（把其中一句拆出短句单独成段）。
- **v1.8 中文（84 章）**：同上一套，另加证据注入与附录 E 制作说明。
- **18 语译文**：跑了**语言无关的结构层**手术（破折号降频 10779 处、列表收尾统一 357 处、段首连接词去重），以及标题模板破除。

### 还剩（如实交代）

- **18 种译文的 R1/R3**：这些改动需要母语判断（在哪里断句、哪句该改短、哪个词换成大白话），本轮没有做。清单在上面，逐条可查。
  译文本来的分级就是 ★★（机翻 + 抽查，质量不承诺），见 `languages.html`。
- **TTS 真人朗读**：本轮**没有**真的用 TTS 播放并逐段听。检测器只能标出「最可能读不顺」的地方，真正的语感判断仍然要人来下结论。
